# Talklog 도메인 모델

**작성**: 2026-09-09 | **범위**: 전략적 DDD (서브도메인 지도 · 유비쿼터스 언어 · 컨텍스트 관계)

이 문서는 기능 명세보다 위에 있는 층이다. `specs/NNN-기능/spec.md`는 "무엇을 만드는가"를
답하고, 이 문서는 **"왜 그것이 먼저인가"**를 답한다.

전술적 DDD 패턴(애그리게이트 · 리포지토리 · 도메인 이벤트 · 값 객체)은 의도적으로
다루지 않는다. 백엔드가 없는 프론트엔드 프로토타입이고, `draft.md` §1이 목적을 "기능
구현이 아니라 사용자가 흐름을 이해하는지 확인"으로 못박아 두었다. Constitution 원칙
IV(최소 의존성)와도 부딪힌다. 필요해지면 이 문서를 개정하고 도입한다.

---

## 1. 제품의 한 문장

> 음성 메시지 앱도 있고 플래시카드 앱도 있다. Talklog는 **그 둘을 잇는 것**이 제품이다.

`draft.md` §1의 검증 질문 다섯 개 중 네 번째가 이 서비스의 존재 이유다.

> 음성 대화에서 플래시카드 학습으로 자연스럽게 이동할 수 있는가?

따라서 Core는 대화도 복습도 아니고, **그 사이의 이음새**다.

## 2. 서브도메인 지도

| 서브도메인 | 책임 (한 문장) | 분류 | 구현 상태 |
|---|---|---|---|
| **표현 학습** | 대화에서 발견한 표현을 학습 자산으로 만든다 | **Core** | 실제 — 002 표현 선택·저장·목록·삭제, 005 표현·뜻 편집 (`localStorage`). AI 문장 다듬기는 Mock |
| **복습** | 저장한 표현을 기억으로 만든다 | Core 지원 | 실제 — 003 오늘 대상·세션·기억 여부·간격 반복·완료 통계 (`localStorage`) |
| 대화 | 학습 짝과 비동기로 음성 메시지를 주고받는다 | Supporting | 부분 — 내가 녹음한 메시지만 실제 |
| 음성 | 목소리를 녹음하고 재생하며 길이를 다룬다 | Supporting | **완료** — [001-voice-recording](../specs/001-voice-recording/) |
| 이해 보조 | 들은 음성을 읽고 뜻을 알 수 있게 한다 (스크립트 · 번역) | Supporting | Mock — 고정 텍스트 토글 |
| 학습 관계 | 누구와 어떤 언어를 공부할지 정한다 | Supporting | 실제 — 004 목록·개설·확인 후 삭제·홈 요약 (`localStorage`). 예시 학습방 별도 제공, 초대 미구현 |
| 계정 | 사용자를 식별한다 | Generic | 없음 |
| 알림 | 돌아올 이유를 만든다 | Generic | 없음 |

### 분류의 뜻

- **Core**: 이 서비스만의 차별점. 직접 설계하고 가장 많이 투자한다.
- **Supporting**: Core를 위해 반드시 필요하지만 차별점은 아니다. 충분히 좋으면 된다.
- **Generic**: 어느 앱에나 있는 것. 나중에 붙이거나 남의 것을 쓴다.

**표현 학습이 Core인 이유**: 음성 녹음이 잘 되어도, 카드 복습이 훌륭해도, 대화에서 표현을
꺼내 카드로 만드는 동작이 어색하면 이 서비스는 두 앱을 억지로 붙인 것이 된다. 반대로 그
이음새만 자연스러우면 나머지가 거칠어도 제품의 주장이 성립한다.

**계정이 Generic이고 후순위인 이유**: 로그인이 없어도 Core 흐름을 검증할 수 있다.
`draft.md` §2가 회원가입을 명시적으로 구현 제외 대상에 넣었다.

## 3. 컨텍스트 관계

```text
[학습 관계] ──학습방 개설──> [대화]
                               │
                          음성 메시지
                               │
                    ┌──────────┴──────────┐
                    ↓                     ↓
                 [음성]              [이해 보조]
              녹음·재생·길이         스크립트·번역
                                          │
                                     스크립트 텍스트
                                          ↓
                                   ★ [표현 학습] ★        ← Core
                                     표현 발견·저장
                                          │
                                        표현
                                          ↓
                                      [복습]
                                   기억 여부·다음 시점

[계정] ── 상류. 모든 컨텍스트가 "누구의 것인지"를 여기서 받는다
[알림] ── 하류. 대화와 복습의 변화를 소비할 뿐 아무것도 결정하지 않는다
```

**Core 사슬**: `음성 → 이해 보조 → 표현 학습 → 복습`. 이것이 `draft.md` §4의 14단계
흐름이고, 프로토타입이 검증해야 하는 축이다.

### 관계 유형

| 상류 → 하류 | 유형 | 계약 |
|---|---|---|
| 음성 → 대화 | Customer/Supplier | 대화는 음성의 길이·재생 가능 여부를 그대로 받는다. `VoiceMessage.source`가 그 계약이다 |
| 이해 보조 → 표현 학습 | Customer/Supplier | 표현 학습은 스크립트 텍스트를 입력으로만 받는다. STT 정확도에 책임지지 않는다 |
| 표현 학습 → 복습 | Customer/Supplier | 복습은 표현을 받아 스케줄만 얹는다. 표현의 뜻·예문을 수정하지 않는다 |
| 계정 → 전부 | Conformist | 다른 컨텍스트는 계정이 주는 식별자를 그대로 쓴다 |
| 대화·복습 → 알림 | 하류 | 알림은 읽기만 한다. 알림 때문에 상류 모델을 바꾸지 않는다 |

## 4. 유비쿼터스 언어

같은 개념을 문서·코드·화면에서 **한 단어로만** 부른다. 아래 "쓰지 않는 말"은 회의에서도
쓰지 않는다.

| 용어 | 코드 식별자 | 정의 | 쓰지 않는 말 |
|---|---|---|---|
| **학습방** | `room` | 한 명의 학습 짝과 하나의 학습 언어로 묶인 대화 공간 | 채팅방, 방, 대화방 |
| **학습 짝** | `partner` | 학습방을 함께 쓰는 상대 | 친구, 상대방, 유저 |
| **음성 메시지** | `VoiceMessage` | 학습방에 놓인, 보낸 사람이 정해진 음성 | 오디오, 보이스, 음성 파일 |
| **녹음** | `VoiceRecording` | 아직 보내지 않은, 전송 전 확인 단계의 음성 | 임시 파일, 드래프트 |
| **스크립트** | `transcript` | 음성을 학습 언어 문자로 옮긴 것 | STT 결과, 원문, 자막 |
| **번역** | `translation` | 스크립트를 사용자의 모국어로 옮긴 것 | 해석, 뜻풀이 |
| **표현** | `Expression` | 학습자가 배우기로 정한 언어 단위. **단어 · 구 · 문장을 모두 포함한다** | 단어, 어휘, 문장, 구문 |
| **다듬은 문장** | `refinedSentence` | 학습자가 말한 문장을 더 자연스럽게 바꾼 것 | 교정, 첨삭, 수정문 |
| **카드** | `Card` | 복습 단위. **표현 하나당 카드 하나** | 플래시카드, 단어카드 |
| **복습** | `review` | 카드를 꺼내 기억 여부를 확인하는 행위 | 학습, 테스트, 퀴즈 |

### 결정 D-1: "표현"이 단어와 문장을 모두 포함한다

`draft.md` §5.6이 **"단어와 문장 중 무엇을 저장하는지 명확한가?"**라고 스스로 묻고 답하지
않았다. 이 문서에서 답한다.

**결정**: 저장 단위는 **표현** 하나이며, 단어(`久しぶり`) · 구(`映画館で映画を見る`) ·
문장(`週末は映画館で映画を見たよ`)을 모두 담을 수 있다. 길이로 종류를 구분하지 않는다.

**근거**: 학습자에게 의미 있는 단위는 문법적 길이가 아니라 "다음에 내가 쓸 수 있는가"다.
현재 UI가 이미 구(`映画館で映画を見る`)를 저장하고 있고, 이를 "단어카드"라 부르면
사용자가 단어만 저장해야 한다고 오해한다.

**결과**: `app/page.tsx`의 `word-card` · `word-index` · `jp-word` · `ko-word` 클래스는
`expression-*`으로 바꾸는 것이 맞다. 표현 학습 기능 명세에서 다룬다.

### 알려진 언어 드리프트 (해소 대상)

| 위치 | 현재 | 있어야 할 것 |
|---|---|---|
| `draft.md` §5.6 | "단어와 문장 중 무엇을" | D-1로 해소됨. draft.md는 기획 초안이므로 수정하지 않고 이 문서가 우선한다 |
| 공통 셸·README | 학습 짝 식별자·스크립트·다듬은 문장·음성 메시지 명칭 | **해소 — 006**. 코드·화면·README를 용어집에 맞췄고 003~005 문서는 추가 위반 없음 |

006에서 공통 셸의 학습 짝 식별자와 README·코드 설명의 스크립트·다듬은 문장·음성 메시지
용어를 정리했다. `app/`·README·003~005 문서의 개념 대체 사용은 해소했으며,
001·002 과거 기능 문서는 이번 정리 대상에서 제외했다.

`app/globals.css` · `app/page.tsx` 의 `.word-card` · `.word-index` · `.jp-word` ·
`.ko-word` · `.flashcard` 와 `README.md` 의 "단어" · "플래시카드" 는
`specs/002-expression-capture` (FR-027)에서 해소했다.

## 5. 서브도메인별 다음 작업

지도에서 도출한 기능 후보다. 번호는 우선순위가 아니라 식별자다.

| 후보 | 서브도메인 | 헌법 제약 | 비고 |
|---|---|---|---|
| 스크립트에서 표현 선택·저장 | 표현 학습 | 없음 | **완료 — 002**. AI 없이 사용자가 직접 선택·저장 |
| 카드 목록·편집 | 표현 학습 | 브라우저 저장소면 통과 | **완료 — 002·005**. 목록·편집·삭제, `expression-*` 이름 정리 |
| 복습 스케줄 | 복습 | 브라우저 저장소면 통과 | **완료 — 003**. 오늘 대상·기억 여부·다음 시점·간격 반복 |
| 학습방 목록·개설 | 학습 관계 | 없음 | **완료 — 004**. 홈 요약·목록·개설·확인 후 삭제 |
| 상대 음성 메시지 수신 | 대화 | 실시간 통신 = Supabase | 헌법 v2.0.0으로 허용. 로그인 선행 |
| 실제 STT·번역 | 이해 보조 | 외부 API, 원칙 VI 경계 | **3단계 첫 기능** (헌법 v2.0.0) |
| 문장 다듬기 | 표현 학습 | 외부 API, 원칙 VI 경계 | 헌법 v2.0.0으로 허용. STT 이후 |
| 로그인 | 계정 | Supabase 인증 | 헌법 v2.0.0으로 허용 |

**백엔드 없이 갈 수 있는 상단 4개는 완료했다.** `draft.md` §4의 표현 저장·카드·복습과
학습방 관리 경로는 실제로 동작한다. 스크립트·번역·AI 문장 다듬기·수신 메시지는 여전히
예시이므로 14단계 전체가 Mock 없이 동작하는 것은 아니다. 실제 전달·자동 분석·계정으로
넘어가기 위해 헌법을 v2.0.0으로 개정했다(2026-10-28): 서버는 Supabase, AI 기능은 제공자
독립 인터페이스(원칙 VI) 뒤에 둔다.

## 6. 이 문서의 위치

- **위**: 없음. 이 문서가 제품 최상위 설계다.
- **옆**: [`.specify/memory/constitution.md`](../.specify/memory/constitution.md) —
  원칙 I이 이 문서를 참조하며, 모든 기능 명세는 소속 서브도메인을 밝혀야 한다.
- **아래**: [`specs/`](../specs/) — 기능별 명세. 각 `spec.md`는 이 문서의 용어집을 따른다.
- **참고**: [`draft.md`](../draft.md) — 기획 초안. 충돌 시 이 문서가 우선한다.

개정 절차는 constitution의 Governance를 따른다. 서브도메인 추가·분류 변경·용어 변경은
이 문서를 고치고, 영향받는 `spec.md`를 함께 갱신한다.

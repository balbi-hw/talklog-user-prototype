# Feature Specification: 실제 스크립트·번역

**Feature Branch**: `007-stt-translation` | **Created**: 2026-10-28 | **Status**: Clarified

**서브도메인**: 이해 보조 (Supporting). 표현 학습(Core)에 스크립트를 공급한다.
**검증 흐름**: `draft.md` §4 6단계 스크립트 확인, 7단계 번역, 10단계 표현 선택.
**Input**: 우선 브리프 007 및 common.md. 로그인·수신·문장 다듬기·음성 영속화·스트리밍은 제외한다.

## User Scenarios & Testing

### User Story 1 - 내가 보낸 음성의 스크립트 확인 (Priority: P1)

내가 녹음해 보낸 음성 메시지의 스크립트를 필요할 때 열어 읽는다.
**Why this priority**: 실제 음성을 표현 학습의 입력으로 연결한다.
**Independent Test**: 녹음 전송 후 스크립트를 열고 닫고 다시 연다.

**Acceptance Scenarios**:

1. **Given** 녹음 메시지, **When** 스크립트를 처음 열면, **Then** 전송 안내와 처리 상태를 표시하고 결과를 보여준다.
2. **Given** 성공한 결과, **When** 닫았다 다시 열거나 학습방을 왕복하면, **Then** 같은 결과를 재사용한다.
3. **Given** 처리 중, **When** 재생·답장·다른 메시지 조작을 하면, **Then** 모두 계속 가능하다.
4. **Given** 외부 서비스 설정이 없음, **When** 요청하면, **Then** 예시 결과라고 명확히 표시한다.

### User Story 2 - 스크립트의 한국어 번역 확인 (Priority: P2)

학습방 언어의 스크립트를 한국어 번역으로 이해한다.
**Why this priority**: 스크립트를 읽는 것만으로 이해하기 어려운 경우를 돕는다.
**Independent Test**: 준비된 스크립트에서 번역을 열어 한국어 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** 스크립트 준비 전, **When** 번역 영역을 보면, **Then** 스크립트를 먼저 열라는 안내가 있다.
2. **Given** 준비된 스크립트, **When** 번역을 처음 열면, **Then** 한국어 번역을 요청하고 이후 재사용한다.
3. **Given** 예시 스크립트, **When** 번역하면, **Then** 번역도 예시 입력에 기반했음을 표시한다.

### User Story 3 - 실패에서 복구하고 표현 저장 (Priority: P3)

실패해도 음성을 듣고 다시 요청할 수 있고, 준비된 스크립트에서 표현을 저장한다.
**Why this priority**: AI가 대화를 막지 않으며 Core로 이어져야 한다.
**Independent Test**: 실패 응답 후 재시도하고 성공한 스크립트에서 표현·뜻을 저장한다.

**Acceptance Scenarios**:

1. **Given** 실패·시간 초과·한도 초과·네트워크 끊김·빈 결과, **When** 해당 영역을 보면, **Then** 상태별 안내와 재시도 수단이 있고 음성은 유지된다.
2. **Given** 실제 스크립트, **When** 범위를 골라 뜻을 적고 저장하면, **Then** 해당 스크립트와 학습방을 예문·출처로 가진 카드가 생긴다.
3. **Given** 키보드 사용, **When** 열기·선택·저장·취소하면, **Then** 모든 조작과 포커스 복귀가 가능하다.

### Edge Cases

- 중복 클릭·다른 학습방 이동 중 완료는 메시지별 결과를 섞거나 중복 요청하지 않는다.
- 말소리 없는 결과는 성공 텍스트로 위장하지 않고 빈 결과로 구분한다.
- 너무 큰 업로드·허용하지 않는 형식·너무 긴 번역 입력은 외부 전송 전에 거절한다.
- 예시 메시지의 고정 텍스트와 AI 피드백 예시 표시는 유지한다.
- 학습방 삭제 시 관련 처리 취소·메모리 해제, 새로고침 시 메시지와 결과 소멸.

## Requirements

### Functional Requirements

- **FR-001**: 내가 녹음해 전송한 메시지의 스크립트는 최초 열기에만 요청하며 같은 세션에서 성공 결과를 재사용해야 한다.
- **FR-002**: 학습방의 일본어·영어·중국어를 스크립트 언어 힌트로 쓰고 번역은 한국어로 제공해야 한다.
- **FR-003**: 번역은 스크립트 준비 후 명시적으로 열 때 요청하고 성공 결과를 재사용해야 한다.
- **FR-004**: 대기·처리 중·성공·실패·시간 초과·사용 한도 초과·네트워크 끊김·빈 결과를 구분하고 실패 후 재시도해야 한다.
- **FR-005**: 요청 중에도 재생·답장·다른 메시지 조작을 허용하고 실패해도 원래 음성을 보존해야 한다.
- **FR-006**: 실제·예시 결과를 구분하고 예시 스크립트 기반 번역도 예시임을 밝혀야 한다. 기존 예시 메시지는 고정 내용을 유지한다.
- **FR-007**: 스크립트에서 표현 선택·편집·뜻 입력·저장을 기존 경로로 연결하고 예문·출처를 보존해야 한다.
- **FR-008**: 음성·텍스트의 외부 제공자 전송을 최초 요청 자리에서 알리고 학습·평가용 데이터를 보관하지 않아야 한다.
- **FR-009**: 업로드 크기·형식·번역 길이·요청 빈도를 제한하고 외부 사용 한도 응답을 한도 초과로 알려야 한다.
- **FR-010**: 모든 조작은 키보드로 가능하고 열기 상태·연결 영역·상태 안내·사라진 버튼의 포커스를 제공해야 한다.
- **FR-011**: 비밀과 제공자별 형식은 서버에만 두고 제공자 교체가 화면·도메인 변경을 요구하지 않아야 한다.

### Key Entities

- **음성 메시지**: 기존 실제 녹음 및 예시. 음성의 수명은 기존 메모리 수명을 따른다.
- **스크립트 / 번역**: 메시지별 텍스트·언어·실제/예시 출처·독립 요청 상태.
- **표현**: 스크립트에서 고른 범위와 뜻·예문·학습방을 기존 표현 모음으로 저장한다.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 녹음 전송 후 스크립트를 한 번의 열기로 요청하고 같은 메시지 재열기에 추가 요청이 0회다.
- **SC-002**: 스크립트·번역 처리 중 재생·답장·다른 메시지 열기의 세 행동이 모두 가능하다.
- **SC-003**: 실패·시간 초과·사용 한도 초과·네트워크 끊김과 빈 결과 모두 안내·재시도가 있고 원래 음성이 남는다.
- **SC-004**: 일본어·영어·중국어 학습방 모두 한국어 번역으로 연결된다.
- **SC-005**: 스크립트에서 저장한 카드의 예문·출처가 해당 스크립트·학습방과 일치한다.
- **SC-006**: 외부 서비스 없이도 예시 경로 전체를 확인할 수 있고 실제 결과로 오해할 표시가 없다.

## Assumptions

- 결과는 메시지와 함께 메모리에만 유지한다. 자동 요청·자동 재시도는 하지 않는다.
- 처리 시간 상한은 서버 30초, 브라우저 40초. 성공한 빈 결과도 재요청은 재시도 버튼으로만 한다.
- 로그인 전 요청 제한은 단일 서버의 완화 수단이며 강한 사용자별 보장을 하지 않는다.

## Clarifications

- 대상·외부 서비스·서버 위치·모델 기본값·Mock 대체·비밀 관리·요청 시점·범위는 우선 브리프 1~11의 확정 결정을 적용했다. 사용자 질문 없음.
- 예시 입력의 번역은 실제 제공자로 처리해도 예시로 표시한다. 결과 출처가 입력보다 신뢰도를 높이지 않는다.
- 크기·시간·빈도 기본값과 구현 근거는 research.md에 기록한다.

# Feature Specification: 카드 편집

**Feature Branch**: `005-expression-edit` | **Created**: 2026-10-27 | **Status**: Implemented (2026-10-27) — 브라우저 검증 대기

**서브도메인**: 표현 학습 (**Core**) — [도메인 모델](../../docs/domain-model.md) §2

**검증하는 흐름 단계**: `draft.md` §4 12단계(생성된 카드 확인), §6의 카드 편집 분리 원칙.

**Input**: 저장한 표현의 뜻을 조금 고치기 위해 예문과 출처까지 지우지 않도록,
카드 목록에서 표현 본문과 뜻을 고치고 새로고침 후에도 유지한다.

## Clarifications

### Session 2026-10-27

질문 없이 기능 브리프의 확정 결정을 반영했다.

- Q: 고칠 수 있는 범위는? → A: 표현 본문과 뜻만. 예문·출처 학습방·저장 시각·식별자는 유지한다.
- Q: 중복 기준은? → A: 앞뒤 공백 제거와 NFC 정규화 후 다른 저장 표현과 비교하며 자기 자신은 제외한다.
- Q: 편집 위치와 포커스는? → A: 목록 항목 안에서 하나만 편집한다. 시작은 뜻 입력칸, 저장·취소 후 해당 편집 버튼으로 돌아온다.
- Q: 삭제와 실패 처리는? → A: 편집과 삭제 확인을 겹치지 않게 하고, 저장소 실패 시 목록과 입력을 유지한다.
- Q: 순서와 기존 데이터는? → A: 저장 시각을 유지하고 기존 필드만 사용한다. Feedback의 저장 전 내용은 편집하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기록을 유지하며 표현과 뜻 고치기 (Priority: P1)

민지는 카드 목록에서 뜻을 보완한다. 표현 본문도 다듬되 실제로 들었던 예문과 출처는 남긴다.

**Why this priority**: 삭제 후 재저장으로 잃던 대화 기록을 보존하는 핵심 가치다.

**Independent Test**: 저장한 카드 하나를 편집하고 새로고침해 결과와 기록을 비교한다.

**Acceptance Scenarios**:

1. **Given** 저장한 표현이 있을 때, **When** 편집을 누르면, **Then** 기존 표현·뜻이 채워지고 뜻 입력칸에 포커스가 간다.
2. **Given** 편집 중일 때, **When** 표현과 뜻을 바꾸고 저장하면, **Then** 목록에 즉시 반영되고 같은 항목의 편집 버튼으로 포커스가 간다.
3. **Given** 편집을 저장했을 때, **When** 새로고침하면, **Then** 수정 결과와 원래 예문·출처·순서·개수가 유지된다.
4. **Given** 편집 중일 때, **When** 취소하면, **Then** 원래 값이 유지되고 편집 버튼으로 포커스가 간다.

### User Story 2 - 잘못된 변경과 중복 막기 (Priority: P2)

민지는 표현이나 뜻을 지웠거나 다른 카드와 같은 표현을 입력하면 이유를 보고 고친다.

**Why this priority**: 유효하지 않은 카드와 중복 카드는 이후 복습의 근거를 훼손한다.

**Independent Test**: 두 카드로 빈 값·문장 부호만 있는 표현·중복·자기 자신의 뜻 변경을 확인한다.

**Acceptance Scenarios**:

1. **Given** 편집 중일 때, **When** 표현이 공백·문장 부호뿐이거나 뜻이 비면, **Then** 저장이 비활성이고 해당 이유가 보인다.
2. **Given** 다른 표현이 있을 때, **When** 그 표현과 정규화 후 같은 본문으로 바꾸면, **Then** 중복 안내가 보이고 저장되지 않는다.
3. **Given** 표현 본문은 그대로일 때, **When** 뜻만 바꾸면, **Then** 자신을 중복으로 오인하지 않고 저장된다.

### User Story 3 - 실패와 삭제 확인 사이에서 입력 지키기 (Priority: P2)

민지는 저장소 실패 후에도 입력을 잃지 않고 다시 저장하거나 취소한다.

**Why this priority**: 실패를 성공처럼 보이게 하거나 입력을 버리지 않아야 한다.

**Independent Test**: 쓰기를 실패시켜 입력 유지·재시도를 확인하고 삭제 확인과 편집이 겹치지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 편집 중 저장소 쓰기가 실패할 때, **When** 저장하면, **Then** 목록은 바뀌지 않고 입력과 실패 안내가 남는다. 복구 후 다시 저장할 수 있다.
2. **Given** 한 카드가 편집 중일 때, **When** 다른 카드를 보면, **Then** 두 번째 편집이나 삭제 확인을 시작할 수 없다. 취소·저장 후 가능해진다.
3. **Given** 삭제 확인 중일 때, **When** 목록을 보면, **Then** 편집은 비활성이다. 삭제 취소 후 편집할 수 있다.
4. **Given** 편집 중 다른 곳에서 대상이 지워졌을 때, **When** 저장하면, **Then** 다시 만들지 않고 대상이 없다는 안내와 입력을 유지한다.

### Edge Cases

- 초기 읽기 중에는 빈 상태를 보여주지 않는다. 빈 목록에는 기존 저장 방법을 안내한다.
- 초기 저장소 접근 실패는 실패 안내를 표시한다. 편집 중 실패는 목록과 입력을 숨기지 않는다.
- 긴 표현과 뜻은 320px 폭에서도 입력칸과 버튼을 밀어내지 않고 줄바꿈한다.
- 화면 이동은 저장하지 않은 편집을 취소한다. 취소 수단이 있으므로 별도 확인 창은 추가하지 않는다.
- 저장 직전 추가된 다른 표현도 중복 검사에 포함하고, 대상의 최신 예문·출처와 다른 항목을 유지한다.
- 여러 탭의 완전히 동시인 쓰기를 원자적으로 병합하는 것은 범위 밖이다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 카드마다 이름을 알 수 있는 편집 수단을 제공하고 해당 항목 안에 기존 표현·뜻을 채운 입력칸과 저장·취소를 표시해야 한다.
- **FR-002**: 한 번에 한 항목만 편집하고 편집 중 다른 항목의 편집과 삭제를 비활성으로 표시해야 한다.
- **FR-003**: 표현 본문과 뜻만 바꾸고 식별자·예문·출처 학습방·저장 시각을 유지해야 한다.
- **FR-004**: 저장 성공은 즉시 목록에 반영하고 완료를 알리며 새로고침 후에도 유지해야 한다.
- **FR-005**: 취소하거나 카드 화면을 떠나면 저장 전 값을 바꾸지 않아야 한다.
- **FR-006**: 기존 표현 저장과 같은 유효성 규칙으로 공백·문장 부호만인 표현과 빈 뜻을 막고 서로 다른 이유를 표시해야 한다.
- **FR-007**: 표현 본문은 앞뒤 공백 제거·NFC 정규화 후 다른 표현과 비교해 중복을 막고 자기 자신을 제외해야 한다.
- **FR-008**: 저장 버튼 비활성 이유는 보이는 문구로 제공해야 한다.
- **FR-009**: 편집 후 목록 순서와 전체 개수는 유지해야 한다.
- **FR-010**: 저장소 읽기·쓰기 실패 시 목록을 바꾸지 않고 실패를 알리며 입력을 유지하고 복구 후 재시도를 허용해야 한다.
- **FR-011**: 저장 직전 최신 저장 내용을 다시 확인해 다른 항목을 보존하고, 대상이 없으면 실패 이유를 알려야 한다.
- **FR-012**: 삭제 확인 중 편집을 막고 편집 중 삭제 확인을 막아야 하며 기존 삭제 확인·취소를 유지해야 한다.
- **FR-013**: 키보드로 전 과정을 조작하고 시작 시 뜻 입력칸, 저장·취소 후 해당 편집 버튼에 포커스를 옮겨야 한다. 여닫는 수단은 펼침 상태와 대상 영역을 알려야 한다.
- **FR-014**: 초기 읽기·빈 목록·저장소 접근 실패를 구분하고 긴 입력에도 모바일 목록을 사용할 수 있어야 한다.
- **FR-015**: 기존 저장 데이터와 저장·삭제 기능을 유지하고 Feedback 저장 전 편집·복습·학습방 화면은 범위에서 제외해야 한다.

### Key Entities

- **표현**: 식별자·본문·뜻·예문·출처 학습방·저장 시각을 가진 기존 저장 항목.
- **편집 중인 표현**: 대상 식별자와 아직 저장하지 않은 본문·뜻. 동시에 하나만 존재하며 성공·취소·화면 이동 시 소멸한다.
- **카드**: 표현 하나에 대응하는 목록 항목. 편집으로 새 카드를 만들지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 카드 목록에서 편집 시작 → 입력 → 저장, 세 단계로 뜻을 고칠 수 있다.
- **SC-002**: 수정 후 새로고침해도 본문·뜻은 변경값이고 예문·출처·순서·개수는 원래와 100% 일치한다.
- **SC-003**: 빈 표현·빈 뜻·다른 표현과 중복·저장소 실패 네 경로에서 각각 이유가 보이고 잘못된 저장은 0건이다.
- **SC-004**: 키보드만으로 편집·저장·취소를 완료하며 시작과 종료 시 지정한 곳에 포커스가 있다.
- **SC-005**: 저장 실패 후 입력한 내용을 다시 적지 않고 재시도할 수 있다.

## Assumptions

- 기존 002 표현 저장과 같은 브라우저 안에서 사용하며 기기 간 동기화는 없다.
- 선택적인 수정 시각은 추가하지 않는다. 기존 데이터를 변환할 필요가 없다.
- 다른 항목 편집으로 현재 입력이 사라지는 것을 막기 위해 편집을 마칠 때까지 나머지 편집·삭제를 비활성으로 둔다.
- 기존 002의 저장 후 편집 제외는 005가 확장한다. 002 문서는 당시 범위를 보존한다.

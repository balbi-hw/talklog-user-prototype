# Phase 0 Research: 학습방 목록·개설

**Feature**: [spec.md](./spec.md) | **Date**: 2026-10-27

## R-001: 진입과 정렬

**Decision**: 대화 탭은 항상 목록, 홈은 최근 활동 순 3개다. 마지막 전송 시각, 없으면 만든 시각, 동률은 id로 정렬한다. 예시 메시지는 예시 시각으로 명시한다.

**Rationale**: 목록 발견을 보장하고 가짜 최근 활동을 피한다.

**Alternatives considered**: 마지막 학습방 직접 입장은 목록 발견이 어려워 제외했다. 활동 시각 영속화는 메시지 영속화 범위와 달라 제외했다.

## R-002: 저장과 복구

**Decision**: talklog.rooms에 사용자 학습방만 JSON 배열로 저장한다. 예시는 상수로 합친다. 모든 접근 try/catch, 첫 effect 읽기, 매 쓰기 직전 재읽기, storage 이벤트·재시도 갱신을 제공한다. 실패 시 기존 상태·초안을 유지한다.

**Rationale**: 002 패턴을 따르고 오래된 탭의 데이터로 덮어쓰는 위험을 줄인다. 탭 간 완전한 원자성은 보장하지 않는다.

**Alternatives considered**: IndexedDB·서버는 필요보다 복잡하다. 예시를 저장하면 수정 가능한 데이터와 혼동되므로 제외했다.

## R-003: 이름과 검증

**Decision**: trim/NFC 후 코드 포인트 1~20자, 언어는 3개 허용 목록. 한글 받침이면 과, 아니면 와. UUID 미지원 환경은 시각+난수 id. 손상 항목·중복 id·예시 id·비정상 시각을 제외한다.

**Rationale**: 조합 입력과 서로게이트 문자를 일관되게 다룬다. 같은 이름의 학습방도 별도 id로 허용한다.

**Alternatives considered**: 비한글 발음 추측은 불명확해 기본 와로 정했다. 이름 중복 금지는 서로 다른 학습 관계를 막아 제외했다.

## R-004: 메시지 생명주기

**Decision**: 셸의 Record<roomId, VoiceMessage[]>에 분리한다. 예시 id만 초기 메시지 2개. 이동 시 녹음 이탈 확인 유지, 삭제 성공 후 해당 Blob URL 해제, 앱 언마운트 시 전송 URL 정리.

**Rationale**: 001 계약을 보존하며 학습방 간 메시지 누출을 막는다.

**Alternatives considered**: 화면 내부 소유는 이동 시 소멸하므로 제외했다. Blob 영속화는 범위 밖이다.

## R-005: 확인과 포커스

**Decision**: 삭제는 인라인 확인으로 aria-expanded/controls 연결. 확인 진입은 취소 버튼, 취소는 삭제 버튼, 성공은 목록 제목으로 포커스 이동. 개설 후 학습방 제목, 개설 취소 후 목록 제목으로 이동. 상태 알림 role=status. 실패해도 예시와 재시도는 제공한다.

**Rationale**: 버튼 소멸 후 포커스가 body로 빠지지 않는다.

**Alternatives considered**: 모달·브라우저 confirm보다 인라인 확인이 작은 셸에서 단순하다.

## 결론

브리프와 기존 코드로 모든 결정을 확정했다. 외부 조사·신규 의존성 없이 설계 후 헌법 게이트를 통과한다.

# Feature Specification: 학습방 목록·개설

**Feature Branch**: `004-room-list` | **Created**: 2026-10-27 | **Status**: Implemented (2026-10-27) — 브라우저 검증 대기

**서브도메인**: 학습 관계 (**Supporting**) — [도메인 모델](../../docs/domain-model.md) §2

**검증하는 흐름 단계**: `draft.md` §4의 2단계(진행 중인 학습방 확인) · 3단계(학습방 입장)

**Input**: 학습방들을 학습 짝·학습 언어로 구분해 선택하고, 새 학습방을 개설해 새로고침 후에도 유지한다. 입장한 학습방에 맞는 머리말과 음성 메시지를 표시한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 학습방을 구분하고 입장하기 (Priority: P1)

민지는 홈에서 진행 중인 학습방을 확인하고 전체 목록에서 원하는 학습 짝과의 대화를 연다.

**Why this priority**: 핵심 흐름의 진입점이며, 대화할 학습 짝과 학습 언어를 혼동하지 않아야 한다.

**Independent Test**: 홈과 대화 메뉴에서 예시 학습방을 열고 머리말·메시지·출처를 확인한다.

**Acceptance Scenarios**:

1. **Given** 앱을 실행한 상태, **When** 홈을 보면, **Then** 최근 활동 순 최대 3개 학습방과 전체 학습방·새 학습방 진입 수단이 보인다.
2. **Given** 대화 메뉴를 누른 상태, **When** 목록을 보면, **Then** 표시 이름·학습 짝·학습 언어·메시지 수와 마지막 메시지 시각(있으면)이 보인다.
3. **Given** 목록의 항목, **When** 입장하면, **Then** 해당 학습방 이름·학습 짝·학습 언어와 해당 메시지만 보인다.
4. **Given** 예시 학습방, **When** 입장하면, **Then** 기존 예시 스크립트·번역·표현 저장 흐름을 계속 사용할 수 있고 출처는 유키와 일본어 대화다.

### User Story 2 - 새 학습방 개설하기 (Priority: P2)

민지는 학습 짝 이름과 학습 언어를 정해 학습방을 만들고 음성 메시지를 녹음한다.

**Why this priority**: 목록 선택을 실제 사용자 데이터로 검증한다.

**Independent Test**: 새 학습방을 만들고 입장·녹음·전송한 후 다른 학습방과 메시지가 섞이지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 개설 화면, **When** 공백뿐이거나 20자를 넘는 이름을 적으면, **Then** 개설을 막고 이유가 보인다.
2. **Given** 유효한 학습 짝 이름, **When** 일본어·영어·중국어 중 하나를 골라 개설하면, **Then** 새 학습방으로 입장하고 이름의 받침에 따라 와/과가 붙는다.
3. **Given** 새 학습방, **When** 처음 입장하면, **Then** 음성 메시지가 없는 안내와 녹음 수단이 보이고 예시 스크립트·번역·피드백은 보이지 않는다.
4. **Given** 전송한 녹음, **When** 다른 학습방을 왕복하면, **Then** 원래 학습방에만 남는다. 새로고침하면 녹음은 사라지지만 학습방 정보는 남는다.
5. **Given** 개설 화면, **When** 취소하면, **Then** 학습방이 만들어지지 않고 목록으로 돌아온다.

### User Story 3 - 학습방 지우기와 실패 복구 (Priority: P3)

민지는 더 이상 쓰지 않는 학습방을 지운다. 저장소가 막히면 실패를 알고 입력을 유지해 재시도한다.

**Why this priority**: 되돌릴 수 없는 동작과 저장 실패를 완결한다.

**Independent Test**: 삭제 취소·확인과 저장소 읽기·쓰기 실패를 각각 검증한다.

**Acceptance Scenarios**:

1. **Given** 사용자 학습방, **When** 지우기를 누르면, **Then** 해당 학습방과 메모리 음성 메시지가 사라짐을 안내하고 취소·확인을 제공한다.
2. **Given** 확인 단계, **When** 취소하면, **Then** 데이터가 유지된다. 확인하면 새로고침 후에도 삭제 상태가 유지된다.
3. **Given** 예시 학습방, **When** 목록을 보면, **Then** 예시 표시가 있고 삭제 수단은 없다.
4. **Given** 저장소 실패, **When** 개설·삭제하면, **Then** 성공으로 표시하지 않고 입력·기존 목록을 유지하며 재시도할 수 있다.

### Edge Cases

- 읽는 중에는 빈 목록으로 단정하지 않는다. 사용자가 만든 학습방이 0개여도 예시 학습방은 항상 남는다.
- 손상된 저장 데이터는 유효한 항목만 사용한다. 중복 id와 예시 id로 저장된 항목은 제외한다.
- 전송 전 녹음이 있으면 목록·홈 이동 전에 기존 버리기 확인을 유지한다.
- 학습방 삭제는 이미 저장한 표현을 지우지 않는다. 출처 문자열은 과거 기록이다.
- 같은 이름·언어로 여러 학습방을 만들 수 있으며 id로 구별한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 홈은 최근 활동 순 최대 3개 실제 학습방과 전체 목록·개설 진입을 제공해야 한다.
- **FR-002**: 대화 메뉴는 학습방 목록을 열고 목록은 표시 이름·학습 짝·학습 언어·메시지 수·마지막 메시지 시각(있으면)을 보여야 한다. 읽지 않은 수를 만들지 않는다.
- **FR-003**: 입장한 학습방의 머리말과 메시지만 표시해야 한다.
- **FR-004**: 유키와 일본어 대화는 삭제 불가 예시 학습방으로 항상 남고 기존 표현 출처와 일치해야 한다.
- **FR-005**: 개설은 앞뒤 공백을 뺀 학습 짝 이름 1~20자와 일본어·영어·중국어 중 하나를 요구해야 한다. 표시 이름은 받침에 맞는 와/과로 파생한다.
- **FR-006**: 개설한 학습방 정보는 새로고침 이후에도 유지해야 한다. 저장 실패 시 초안을 유지하고 재시도를 제공해야 한다.
- **FR-007**: 새 학습방은 빈 상태와 녹음·전송을 제공하고 스크립트·번역·표현 고르기·예시 피드백은 예시 학습방에서만 제공해야 한다.
- **FR-008**: 음성 메시지는 학습방별로 분리하고 새로고침 전까지 유지해야 한다. 영속화하지 않음을 알려야 한다.
- **FR-009**: 사용자 학습방 삭제는 확인·취소를 거쳐야 한다. 성공한 삭제만 목록과 메시지에서 제거하고 저장한 표현은 유지해야 한다.
- **FR-010**: 읽기 대기·빈 상태·읽기 실패·쓰기 실패를 구분해야 한다. 손상된 항목 때문에 정상 항목을 잃지 않아야 한다.
- **FR-011**: 초대·알림·실제 전달이 미구현임을 알리고 초대처럼 보이는 동작을 제공하지 않아야 한다.
- **FR-012**: 새 컨트롤은 키보드 조작·명확한 라벨·상태 알림을 제공하고 개설·취소·삭제 전이 후 포커스를 유효한 위치로 옮겨야 한다.
- **FR-013**: 녹음 중 학습방을 떠나는 기존 확인 단계를 보존해야 한다.

### Key Entities

- **학습방 (`room`)**: 식별자·학습 짝 이름·학습 언어·만든 시각. 표시 이름은 파생한다.
- **예시 학습방**: 고정 id와 예시 메시지를 가진 삭제 불가 학습방.
- **음성 메시지 (`VoiceMessage`)**: 셸이 학습방 id별로 소유하는 메모리 데이터.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 홈에서 한 번 선택하거나 대화 메뉴와 목록 항목을 두 번 선택해 원하는 학습방으로 입장한다.
- **SC-002**: 학습 짝 3명·학습 언어 3개로 개설한 학습방을 목록·머리말에서 정확히 구분한다.
- **SC-003**: 개설·삭제 결과가 새로고침 이후에도 일치하며 서로 다른 학습방의 메시지가 섞이는 경우가 0건이다.
- **SC-004**: 실패 시 데이터 성공 표시가 0건이고 초안과 재시도 수단이 남는다.
- **SC-005**: 키보드만으로 개설·입장·삭제 취소·삭제 확인을 완료한다.

## Assumptions

개인 대화만 다룬다. 초대·계정·동기화·실제 전달·음성 메시지 영속화·STT는 범위 밖이다. 예시 메시지의 시각은 실제 활동처럼 환산하지 않고 예시 시각으로 명시한다.

## Clarifications

### Session 2026-10-27

브리프의 확정 결정을 적용해 질문 없이 정리했다. 이름은 NFC 정규화 후 코드 포인트 1~20자로 센다. 비한글 끝 글자는 와를 기본값으로 쓴다. 대화 메뉴는 항상 목록으로 간다. 홈은 최근 활동 순 3개이며 새 학습방은 만든 시각, 녹음 전송 이후에는 전송 시각을 정렬에 쓴다. 삭제 후 목록 제목으로, 개설 후 학습방 제목으로 포커스를 옮긴다.

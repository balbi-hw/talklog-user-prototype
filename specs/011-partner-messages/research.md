# Research: 학습 짝 초대와 음성 메시지 주고받기

## R1. 함께 쓰는 학습방을 어떻게 나타내나

- **결정**: 010 의 `rooms`(사용자별 행)는 그대로 두고, 공유 정보를 새 테이블 `shared_rooms` 에 둔다. 한 행이 "만든 사람의 학습방 하나"에 대응한다(`owner_id`, `owner_room_id` 유일).
  - 만든 사람은 자기 `rooms` 행(010)으로 학습방을 본다.
  - 들어온 학습 짝은 자기 `rooms` 에 `id = shared_rooms.id` 인 행을 하나 만든다. 010 동기화·목록·홈 요약을 고치지 않고 그대로 쓴다.
  - 표시 이름은 `shared_rooms.owner_name`·`partner_name` 이 우선한다. `rooms.partner` 는 학습 짝이 들어오기 전이나 공유 정보를 받아 오기 전의 대체값이다.
- **근거**: 010 의 학습방 id 는 사용자 안에서만 유일하다. 공유용 전역 id 가 따로 필요하다. 목록을 공유 정보에서만 만들면 010 의 학습방 목록·삭제·홈 요약을 두 갈래로 나눠야 한다.
- **대안**: `rooms` 를 공유 테이블로 바꾸기. 010 의 RLS·동기화·가져오기를 모두 다시 써야 해서 버렸다.
- **복구 규칙**: 공유 정보를 받아 왔는데 내가 학습 짝이고 나가지 않은 학습방의 `rooms` 행이 없으면(들어오기 직후 쓰기 실패, 다른 기기) 다시 만든다. 만든 사람 쪽은 복구하지 않는다(010 행이 원본).

## R2. 초대 코드와 들어오기는 어디서 검사하나

- **결정**: Postgres 함수(`security definer`, `search_path = ''`)로 한다. `create_invite`·`revoke_invite`·`preview_invite`·`accept_invite`·`leave_shared_room`·`ensure_shared_room`. 클라이언트는 `supabase.rpc` 로 부른다. `invite_codes` 테이블은 클라이언트에 권한을 주지 않는다.
- **근거**: 들어오려는 사람은 아직 멤버가 아니어서 RLS 로는 코드를 볼 수 없다. 코드 검사·사용 표시·학습 짝 지정은 한 트랜잭션이어야 두 사람이 같은 코드를 동시에 써도 한 명만 들어온다(`for update`). 헌법은 별도 백엔드 서버를 금지하고 Edge Function 은 이 일에 과하다.
- **실패 반환**: 예외 대신 `jsonb {ok:false, reason}` 를 돌려준다. 예외는 트랜잭션을 되돌려 실패 시도 기록(R3)까지 지운다.
- **표시 이름**: 함수가 `auth.jwt() -> 'user_metadata' ->> 'display_name'` 에서 읽고 1~20자로 자른다. 없으면 이메일 앞부분이다(009 `toAccountUser` 와 같은 규칙). 클라이언트가 보낸 이름은 믿지 않는다.

## R3. 코드 추측 막기

- **결정**: 코드는 `23456789ABCDEFGHJKMNPQRSTUVWXYZ`(31자, 0·O·1·I·L 제외)에서 6자, 약 8.9억 가지다. `invite_attempts` 에 실패를 남기고, 10분 안에 실패가 10번이면 `too-many` 를 돌려준다. 24시간 만료, 한 번 사용, 학습방당 유효 코드 1개.
- **근거**: 10분에 10번이면 하루 최대 1,440번이라 맞힐 확률은 무시할 만하다. 코드 생성은 `gen_random_bytes`(pgcrypto, Supabase 기본 설치) 로 한다.

## R4. 소리는 어디에, 어떻게 재생하나

- **결정**: Storage 비공개 버킷 `voice-messages`. 경로는 `<shared_room_id>/<sender_id>/<message_id>`. 재생·스크립트용 주소는 `createSignedUrls` 로 1시간짜리를 한 번에 받는다. 50분이 지났으면 창 복귀·학습방 열기 때 다시 받는다.
- **근거**: 서명 주소는 `<audio src>` 와 007 의 `fetch(message.url)` 에 그대로 쓸 수 있어 재생·스크립트 코드를 고치지 않는다. 미리 내려받아 blob 주소로 만들면 기록이 길어질수록 메모리를 쓴다.
- **정책**: `storage.objects` 에 버킷 한정 정책. 읽기는 경로 첫 폴더의 학습방 멤버, 쓰기는 멤버이면서 둘째 폴더가 자기 id 이고 학습방이 닫히지 않았을 때, 지우기는 멤버. 크기 상한 5MB, 허용 형식 `audio/webm`·`audio/mp4`·`audio/ogg`·`audio/mpeg`(001 녹음 후보와 같다).
- **지우기**: Storage 객체는 SQL 로 지울 수 없다(Storage API 전용). 마지막으로 나가는 사람의 클라이언트가 그 학습방 폴더를 지운 뒤 `leave_shared_room` 을 부른다. 지우기가 실패해도 나가기는 진행하고, 남은 객체는 아무도 읽을 수 없다(멤버가 없으므로).

## R5. 보내기 순서와 다시 보내기

- **결정**: 클라이언트가 `message_id`(uuid)를 먼저 만든다.
  1. 소리를 올린다(`upsert: false`). 이미 있다는 응답(409)은 성공으로 본다.
  2. `voice_messages` 에 넣는다. 같은 id 충돌(23505)도 성공으로 본다.
  3. 서버가 돌려준 `created_at` 으로 위치를 정한다.
  실패하면 메시지를 "보내지 못했어요"로 두고, 다시 보내기는 같은 id 로 1부터 한다.
- **근거**: 같은 id 로 다시 보내면 FR-007·SC-005(중복 0건)가 성립한다. 소리 없이 행만 생기면 재생할 수 없는 메시지가 보이므로 소리를 먼저 올린다.
- **시간 상한**: 올리기 30초, 행 넣기·함수·목록 15초(010 과 같다). 넘으면 `timeout`.
- **보내는 중인 메시지**: 메모리에만 둔다. 화면을 떠나거나 새로고침하면 사라진다. 떠나기 전 확인은 001 의 녹음 확인과 같은 방식으로 "보내는 중인 메시지가 있어요"를 더한다.
- **고아 소리**: 소리를 올린 뒤 행을 넣기 전에 로그아웃·새로고침하면 행 없는 Storage 객체가 남는다. 받아들인다 — 행이 없어 아무 화면에도 보이지 않고, 마지막 멤버가 나갈 때 폴더째 지워진다. 로그아웃 확인은 보내는 중·실패한 메시지 수를 알린다 (D8).

## R6. 새 메시지를 바로 받기

- **결정**: Supabase Realtime **Postgres Changes** 로 `voice_messages` INSERT 와 `shared_rooms` UPDATE 를 받는다. 로그인 사용자당 채널 하나를 연다. 테이블을 `supabase_realtime` publication 에 넣는다. RLS 가 구독자별로 적용되어 멤버인 학습방의 행만 온다.
- **근거**: 추가 의존성이 없고(`@supabase/supabase-js` 2.118 에 포함), 이 규모(사람 둘)에는 Broadcast 트리거·`realtime.messages` 정책까지 둘 이유가 없다.
- **빠진 메시지**: 채널이 `SUBSCRIBED` 가 될 때, `online`·`focus`, 학습방을 열 때 그 학습방의 메시지를 다시 받아 id 로 합친다. 한 번에 최근 500개다.
- **연결 상태**: `connecting`·`live`·`lost`. `CHANNEL_ERROR`·`TIMED_OUT`·`CLOSED` 면 `lost` 이고 15초 뒤 다시 연결한다. 학습방에 안내와 다시 시도를 보인다(FR-010).
- **대안**: 주기적으로 받아 오기. 5초 안(SC-002)을 맞추려면 요청이 많아진다.

## R7. 어떤 학습방이 서버 메시지를 쓰나

- **결정**: 로그인 상태이고 계정 기록(010)을 받아 온 뒤의 모든 내 학습방(예시 학습방 제외). 처음 메시지를 보내거나 초대 코드를 만들 때 `ensure_shared_room` 으로 공유 정보를 만든다.
- **근거**: 학습 짝이 나중에 들어와도 그 전 메시지를 본다(US2-4). 로그아웃·키 없음·예시 학습방은 지금 메모리 경로 그대로다(FR-013).
- **010 과의 관계**: 학습방을 만든 직후 010 의 `rooms` 행이 아직 대기열에 있어도 `ensure_shared_room` 은 동작한다. 함수는 `rooms` 를 참조하지 않고 학습 언어를 인자로 받는다.

## R8. 나가기

- **결정**: 공유 정보가 있는 학습방을 지우면, 온라인으로 먼저 `leave_shared_room` 을 부르고 성공하면 010 경로로 내 `rooms` 행을 지운다. 실패하면 지우지 않고 이유를 알린다.
  - 두 사람 모두 나갔거나, 학습 짝이 없는데 만든 사람이 나가면 함수가 `shared_rooms` 를 지운다. 메시지·코드는 cascade 로 함께 지워진다.
  - 그 전에 클라이언트가 R4 대로 소리를 지운다.
- **근거**: 나가기를 대기열로 미루면, 연결이 없는 동안 목록에서는 사라졌는데 학습 짝에게는 아직 있는 상태가 된다. 확인 단계가 이미 있어서 온라인을 요구해도 흐름이 크게 늘지 않는다.

## R9. 로그아웃·계정 바뀜

- **결정**: 공유 정보·메시지·서명 주소·보내는 중인 메시지는 모두 메모리 상태이고, 사용자 id 가 바뀌면 버리고 채널을 닫는다. localStorage 에 새 키를 만들지 않는다.
- **근거**: FR-014. 010 의 계정 사본 삭제 규칙에 추가할 키가 없다.

## R10. 검증 방법

- **자동**: 010 과 같이 Playwright 에서 가짜 Auth·PostgREST·Storage(`page.route`)와 가짜 Realtime(`page.routeWebSocket`, playwright-core 1.64)으로 두 브라우저 문맥을 돌린다. 실제 계정은 만들지 않는다.
- **실제 DB**: 사용자가 마이그레이션을 적용하고, 직접 만든 두 계정으로 R 항목을 확인한다. anon 차단과 다른 계정 차단은 REST 로 확인한다.

## 검증 후 보완 (D1~D10)

독립 검증(가짜 Auth·PostgREST·Storage·Realtime, 두 문맥)에서 나온 결함을 이렇게 고쳤다.

- **D1 처음 보낸 메시지가 사라짐**: `ensure_shared_room` 결과로 최소 공유 정보 행을 곧바로 상태에 넣는다. 서버 목록에 보일 때까지 남겨 두므로, 늦게 온 받아 오기나 받아 오기 실패에도 메시지가 이어서 보인다. 같은 id 라 중복은 없다.
- **D2 새로고침 뒤 유효 코드가 안 보임**: RPC `current_invite(p_room_id)`(만든 사람만, security definer, `search_path = ''`, authenticated 만 실행)를 더했다. 학습방을 열 때 받아 와 코드·남은 시간·취소를 다시 보인다.
- **D3 공유 정보 첫 받아 오기 실패**: 공유 정보를 모르는 학습방은 오류 대신 `unknown` 으로 "학습방 정보를 받아 오면 지난 음성 메시지가 보여요"를 보이고 녹음·전송은 그대로 된다. 15초마다, 그리고 online·focus 때 다시 받아 온다. 지우기는 공유 정보가 있으면 나가기로, 받아 온 뒤 없으면 그냥 지우기로 하고, 모르면 이유를 알리고 막는다.
- **D4 만료된 서명 주소**: 재생 다시 시도는 그 메시지의 새 서명 주소를 받은 뒤 재생하고, 학습방 전체를 다시 서명한다.
- **D5** 초대 코드 확인 대화상자에서 Tab·Shift+Tab 이 대화상자 안에서만 돈다.
- **D6** 다시 보내기·다시 재생 뒤에는 그 메시지의 재생 버튼으로, 지우기 뒤에는 학습방 제목으로 포커스를 옮긴다.
- **D7** 키 없는 환경 문구는 구현대로 두고 spec US5-1 을 고쳤다.
- **D8** 로그아웃 확인에 보내는 중·실패한 음성 메시지 수를 알린다. 고아 소리는 R5 에 적었다.
- **D9** 실시간 행이 넣기 응답보다 먼저 오면 같은 id 의 보내는 중·실패 항목을 빼고, 그 blob 주소는 서버 메시지가 이어 쓴다(revoke 는 로그아웃·나가기 때).
- **D10** 나가기가 시간 초과·연결 끊김으로 실패하면 공유 정보를 다시 받아, 서버에서 이미 나갔거나 학습방이 지워졌으면 나가기를 마친다.
- **참고**: storage-js 2.118 은 Blob 을 올릴 때 `contentType` 대신 Blob 의 형식을 쓴다. 허용 형식과 맞도록 `;codecs=` 를 뗀 형식으로 Blob 을 다시 감싸 올린다.

- **N1 (D1 보완의 부작용)**: 학습 짝 쪽(`rooms.id` = 공유 id)에서 보낸 직후 임시 공유 정보를 만든 사람 역할로 두던 것을 학습 짝 역할로 둔다. 임시 공유 정보뿐인 학습방의 나가기는 서버 목록을 다시 받아 확인한 뒤에만 하고, 확인하지 못하면 소리를 지우지 않고 멈춘다(이때 문구는 연결 끊김 문구를 쓴다).

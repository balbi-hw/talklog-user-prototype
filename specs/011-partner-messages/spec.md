# Feature Specification: 학습 짝 초대와 음성 메시지 주고받기

**Feature Branch**: `011-partner-messages` | **Created**: 2026-11-02 | **Status**: Implemented (실제 DB 확인 완료)
**Input**: 3단계 마지막 묶음의 앞부분. 로그인한 사용자가 학습방에서 초대 코드를 만들어 학습 짝에게 알려 주고, 학습 짝이 로그인한 상태에서 코드를 입력하면 같은 학습방에 들어온다. 두 사람은 음성 메시지를 녹음해 보내고, 앱을 열어 둔 동안 상대가 보낸 새 메시지를 바로 받아 재생하고 스크립트·번역을 본다. 사용자 결정: 초대는 **초대 코드**, 알림은 **앱 안에서만**이며 새 메시지 표시·개수는 **012** 로 나눈다. 010 계정 기록 위에 쌓는다.
**서브도메인**: 대화(Supporting)가 처음으로 두 사람 사이에서 실제로 오간다. 학습 관계(Supporting)에 초대가 생긴다. 계정(Generic)은 누가 보냈는지를 정한다.
**흐름**: draft.md §4 의 **2 진행 중인 학습방 확인**(들어온 학습방이 목록에 보임), **4 학습 짝의 음성 메시지 확인**, **5 음성 재생**, **6 생성된 스크립트 확인**(학습 짝 메시지), **9 답장 전송**(학습 짝에게 실제로 전달)을 검증한다.

## User Scenarios & Testing

### User Story 1 - 초대 코드로 학습 짝을 학습방에 들인다 (Priority: P1)

로그인한 학습자가 자기가 만든 학습방에서 초대 코드를 만든다. 코드를 메신저나 말로 학습 짝에게 알려 주고, 학습 짝은 로그인한 상태에서 코드를 입력해 같은 학습방에 들어온다.

**Why this priority**: 학습 짝이 학습방에 없으면 메시지를 주고받을 수 없다. 나머지 이야기 모두가 여기에 기댄다.

**Independent Test**: 브라우저 A(계정 1)에서 학습방을 만들고 초대 코드를 만든다. 브라우저 B(계정 2)에서 코드를 입력한다. B 의 학습방 목록에 그 학습방이 보이고, A 의 학습방에는 학습 짝이 들어왔다고 보인다.

**Acceptance Scenarios**:

1. **Given** 로그인 상태이고 학습 짝이 아직 없는 내 학습방, **When** 초대 코드 만들기를 누른다, **Then** 6자리 코드와 남은 유효 시간이 보이고 코드를 복사할 수 있다.
2. **Given** 유효한 코드, **When** 다른 계정으로 로그인한 사람이 학습방 목록의 "초대 코드 입력"에 코드를 넣는다, **Then** 들어갈 학습방(만든 사람의 표시 이름·학습 언어)을 확인한 뒤 들어가고, 그 학습방이 열린다.
3. **Given** 학습 짝이 들어옴, **When** 만든 사람이 학습방을 본다, **Then** 학습 짝의 표시 이름이 보이고 초대 코드는 더 이상 보이지 않는다.
4. **Given** 코드가 틀렸거나 만료됐거나 이미 쓰였음, **When** 입력한다, **Then** 각각 다른 이유를 알려 주고 아무 학습방에도 들어가지 않는다.
5. **Given** 내가 만든 학습방의 코드, **When** 내가 입력한다, **Then** 내 학습방이라 들어갈 수 없다고 알린다.
6. **Given** 초대 코드가 보이는 중, **When** 코드를 취소하거나 새로 만든다, **Then** 이전 코드는 바로 쓸 수 없게 된다.

---

### User Story 2 - 학습 짝에게 음성 메시지를 보낸다 (Priority: P1)

학습 짝이 있는 학습방에서 녹음하고 미리 들은 뒤 보내면, 그 음성 메시지가 학습 짝에게 전달된다. 새로고침하거나 다른 기기에서 열어도 메시지가 남아 있다.

**Why this priority**: 흐름 9단계 "답장 전송"이 지금은 학습 짝에게 전달되지 않는다. 이 기능의 핵심 주장이다.

**Independent Test**: A 에서 녹음 → 전송 → 새로고침해도 메시지가 남는다. B 에서 그 학습방을 열면 A 의 메시지가 학습 짝 메시지로 보인다.

**Acceptance Scenarios**:

1. **Given** 학습 짝이 있는 학습방, **When** 녹음을 미리 듣고 전송한다, **Then** 메시지가 바로 대화에 "보내는 중"으로 놓이고, 다 보내면 보낸 시각이 표시된다.
2. **Given** 보내는 중 연결이 끊기거나 서버가 거부함, **When** 전송이 실패한다, **Then** 메시지는 "보내지 못했어요"와 다시 보내기·지우기를 보이고, 녹음은 이 화면을 떠나기 전까지 남아 있다 (원칙 V).
3. **Given** 보낸 메시지, **When** 새로고침하거나 같은 계정으로 다른 기기에서 학습방을 연다, **Then** 같은 메시지가 같은 순서로 보이고 재생된다.
4. **Given** 학습 짝이 아직 없는 내 학습방(로그인 상태), **When** 메시지를 보낸다, **Then** 메시지는 계정에 저장되고, 나중에 들어온 학습 짝도 그 메시지를 본다.

---

### User Story 3 - 학습 짝의 새 메시지를 바로 받아 듣고 이해한다 (Priority: P1)

앱을 열어 둔 동안 학습 짝이 보낸 메시지가 새로고침 없이 대화에 나타난다. 재생하고, 스크립트와 번역을 요청해 볼 수 있다.

**Why this priority**: 흐름 4·5·6단계가 지금은 예시 메시지로만 동작한다.

**Independent Test**: A 와 B 가 같은 학습방을 연 채로 B 가 메시지를 보낸다. A 의 대화에 몇 초 안에 그 메시지가 나타나고 재생된다. 스크립트·번역을 요청하면 결과가 보인다.

**Acceptance Scenarios**:

1. **Given** 학습방을 열어 둔 A, **When** B 가 메시지를 보낸다, **Then** A 의 대화 끝에 학습 짝 메시지로 나타난다. A 가 다른 화면에 있었다면 그 학습방을 열 때 보인다.
2. **Given** 학습 짝 메시지, **When** 재생을 누른다, **Then** 소리가 재생된다. 소리를 받아 오지 못하면 재생 실패와 다시 시도를 보이고 다른 메시지와 녹음은 계속 쓸 수 있다.
3. **Given** 학습 짝 메시지, **When** 스크립트를 연다, **Then** 내 메시지와 같은 방식(007)으로 스크립트를 요청하고, 성공하면 번역을 요청할 수 있으며 스크립트에서 표현을 골라 저장할 수 있다(002). 다듬기(008)는 내 메시지에만 있다.
4. **Given** 연결이 끊겼다가 돌아오거나 창으로 돌아옴, **When** 그사이 학습 짝이 메시지를 보냈다, **Then** 빠진 메시지를 받아 와 시간 순서대로 넣는다. 같은 메시지가 두 번 보이지 않는다.
5. **Given** 바로 받는 연결을 맺지 못함, **When** 학습방을 본다, **Then** "새 메시지를 바로 받지 못하고 있어요"와 다시 시도를 보이고, 대화는 계속 쓸 수 있다.

### User Story 4 - 학습방에서 나간다 (Priority: P2)

학습 짝이 있는 학습방을 지우면 나에게서만 사라지고, 학습 짝에게는 내가 나갔다고 보인다.

**Why this priority**: 함께 쓰는 학습방을 한쪽이 지웠을 때 다른 쪽 기록이 사라지면 안 된다.

**Independent Test**: B 가 학습방을 지운다. B 의 목록에서 사라지고, A 의 학습방에는 "학습 짝이 나갔어요"가 보이며 녹음·전송이 막힌다.

**Acceptance Scenarios**:

1. **Given** 학습 짝이 있는 학습방, **When** 학습방 목록에서 지우기를 누른다, **Then** 확인 단계에서 "나가면 이 학습방의 메시지를 더 볼 수 없어요"를 알리고, 확인하면 내 목록에서 사라진다.
2. **Given** 학습 짝이 나간 학습방, **When** 남은 사람이 연다, **Then** 지난 메시지는 그대로 보이고, 녹음·전송 자리에 학습 짝이 나갔다는 안내가 보인다. 이 학습방은 다시 초대할 수 없다.
3. **Given** 두 사람 모두 나감, **When** 시간이 지난다, **Then** 그 학습방의 메시지와 소리는 누구도 볼 수 없다.

---

### User Story 5 - 로그인하지 않아도, 예시 학습방도 지금처럼 (Priority: P1)

**Why this priority**: 로그인은 선택이다(009). 기존 흐름을 깨면 안 된다.

**Acceptance Scenarios**:

1. **Given** 로그아웃 또는 키 없는 환경, **When** 학습방에서 녹음·전송한다, **Then** 지금처럼 이 브라우저 메모리에만 놓이고, 초대 코드 만들기와 입력 자리에 로그아웃 상태면 "로그인하면 학습 짝을 초대할 수 있어요"와 로그인으로 가는 버튼이, 키 없는 환경이면 "이 환경에서는 로그인을 쓸 수 없어 학습 짝을 초대할 수 없어요"가 보인다 (로그인 자체를 쓸 수 없는 환경에서 로그인을 권하지 않는다, 원칙 II).
2. **Given** 예시 학습방, **When** 연다, **Then** 예시 메시지와 예시 스크립트·번역이 지금처럼 보이고 초대할 수 없다.
3. **Given** 로그아웃, **When** 학습방 목록을 본다, **Then** 계정의 학습방과 학습 짝 메시지는 이 기기에 남지 않는다.

### Edge Cases

- 초대 코드는 한 학습방에 동시에 하나만 유효하다. 24시간이 지나면 만료된다.
- 학습 짝은 한 학습방에 한 명이다. 이미 학습 짝이 있는 학습방의 코드는 만들 수 없다.
- 이미 들어온 학습방의 코드를 다시 입력하면 그 학습방을 연다.
- 코드는 대소문자와 앞뒤 공백을 가리지 않는다. 헷갈리는 글자(0/O, 1/I/L)는 코드에 쓰지 않는다.
- 같은 사람이 짧은 시간에 틀린 코드를 여러 번 넣으면 잠시 입력을 막는다 (코드 추측 방지).
- 들어온 학습 짝에게 학습방의 학습 언어는 만든 사람이 정한 그대로다. 학습방 이름은 각자 상대의 표시 이름으로 보인다.
- 메시지를 보내는 중에 학습방을 떠나려 하면 지금처럼(001) 떠나기 확인을 거친다.
- 녹음 상한은 지금처럼 60초다.
- 두 사람이 거의 동시에 보내면 서버가 받은 순서대로 놓인다.
- 학습 짝 메시지의 스크립트·번역 결과는 지금처럼 이 화면을 쓰는 동안만 남는다. 다시 열면 다시 요청한다.
- 메시지를 보낸 뒤 지우거나 고치는 기능은 없다.
- 로그인했지만 계정 기록(010)을 아직 받아 오지 못했으면 초대·메시지 기능도 받아 오는 중으로 보인다.

## Requirements

### Functional Requirements

- **FR-001**: 로그인한 사용자는 자기가 만든, 학습 짝이 없는 학습방에서 초대 코드를 만들 수 있다. 코드는 6자리이고 24시간 동안 한 번만 쓸 수 있다.
- **FR-002**: 초대 코드를 만든 사람은 코드를 복사하고, 취소하고, 새로 만들 수 있다. 새로 만들거나 취소하면 이전 코드는 바로 쓸 수 없다.
- **FR-003**: 로그인한 사용자는 학습방 목록에서 초대 코드를 입력하고, 들어갈 학습방을 확인한 뒤 들어간다. 들어간 학습방은 내 학습방 목록에 보이고 바로 열린다.
- **FR-004**: 코드 입력 실패는 이유별로 다른 문구를 보인다: 형식이 틀림, 없는 코드, 만료됨, 이미 쓰임, 내 학습방, 학습 짝이 이미 있음, 너무 많이 시도함, 연결 끊김, 시간 초과.
- **FR-005**: 학습방의 두 사람은 그 학습방의 메시지를 읽고 보낼 수 있다. 다른 사람은 학습방, 메시지, 소리 어느 것도 읽거나 쓸 수 없다.
- **FR-006**: 로그인 상태에서 보낸 음성 메시지는 소리와 함께 계정에 저장되고, 새로고침·다른 기기에서도 같은 순서로 보인다.
- **FR-007**: 전송은 보내는 중·보냄·실패 상태를 메시지에 보인다. 실패한 메시지는 다시 보내거나 지울 수 있고, 다시 보내도 메시지가 두 번 놓이지 않는다.
- **FR-008**: 앱을 열어 둔 동안 학습 짝이 보낸 메시지는 새로고침 없이 그 학습방 대화에 나타난다.
- **FR-009**: 연결이 돌아오거나, 창으로 돌아오거나, 학습방을 열면 빠진 메시지를 받아 온다. 같은 메시지는 한 번만 보인다.
- **FR-010**: 바로 받는 연결이 끊기면 학습방에 그 사실과 다시 시도를 보이고, 재생·녹음·전송은 막지 않는다.
- **FR-011**: 학습 짝 메시지는 재생할 수 있고, 내 메시지와 같은 방식으로 스크립트·번역을 요청하고 스크립트에서 표현을 저장할 수 있다. 소리를 받아 오지 못하면 재생 실패와 다시 시도를 보인다.
- **FR-012**: 학습 짝이 있는 학습방을 지우는 것은 나가기다. 확인 단계를 거치고, 내 목록에서만 사라지며, 남은 사람에게는 학습 짝이 나갔다고 보이고 보내기가 막힌다.
- **FR-013**: 로그아웃 상태, 키 없는 환경, 예시 학습방은 지금처럼 동작한다. 초대 자리는 로그인이 필요하다고 알린다 (원칙 II: 동작하지 않는 버튼처럼 보이지 않는다).
- **FR-014**: 로그아웃하면 이 기기에서 계정의 학습방·메시지·소리를 지운다 (010 FR-009 와 같은 규칙).
- **FR-015**: 화면 문구는 사실과 맞아야 한다. 010 에서 "녹음은 올라가지 않는다"고 알리던 문구를 이 기능에 맞게 바꾼다.

### Key Entities

- **학습방(공유)**: 만든 사람, 학습 짝(없거나 한 명), 학습 언어, 학습 짝이 나갔는지. 두 사람이 같은 학습방을 본다.
- **초대 코드**: 학습방, 코드, 만든 시각, 만료 시각, 쓰였는지·취소됐는지.
- **음성 메시지(계정)**: 학습방, 보낸 사람, 길이, 서버가 받은 시각, 소리. 보낸 사람 기준으로 "나"와 "학습 짝"이 갈린다.
- **보내는 중인 메시지**: 아직 서버가 받지 않은 내 메시지. 상태(보내는 중·실패)와 녹음을 가진다. 이 화면을 쓰는 동안만 있다.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 초대 코드를 받은 학습 짝이 코드 입력부터 학습방이 열리기까지 30초 안에 끝낸다.
- **SC-002**: 두 사람이 같은 학습방을 열어 둔 상태에서, 보낸 메시지가 상대 화면에 5초 안에 나타난다 (연결이 정상일 때 10번 중 9번 이상).
- **SC-003**: 연결이 끊긴 동안 학습 짝이 보낸 메시지가 복구 후 100% 보이고, 중복은 0건이다.
- **SC-004**: 학습방 멤버가 아닌 계정으로는 그 학습방의 메시지·소리를 0건 읽을 수 있다.
- **SC-005**: 실패한 전송을 다시 보낸 뒤 대화에 같은 메시지가 두 번 있는 경우가 0건이다.
- **SC-006**: 로그아웃 상태의 녹음·전송·재생·스크립트 흐름은 010 과 같은 결과를 낸다 (회귀 0건).

## Assumptions

- 학습 짝 초대는 같은 서비스에 가입한 사람끼리만 한다. 가입하지 않은 사람에게 코드를 보내면, 그 사람은 가입·로그인한 뒤 입력한다.
- 학습방 하나에 학습 짝은 한 명이다 (용어집의 학습방 정의). 여러 명 학습방은 범위 밖이다.
- 이미 계정에 있는 학습방(010)도 초대할 수 있다. 그 학습방에서 로그인 상태로 보낸 메시지는 이 기능부터 계정에 저장된다. 010 이전에 메모리로만 있던 녹음은 옮기지 않는다.
- 학습방의 "학습 짝 이름"은 만든 사람이 직접 적은 이름이었다(004). 학습 짝이 들어오면 두 사람 모두 상대의 표시 이름(009)으로 학습방을 본다.
- 새 메시지 표시, 안 읽은 개수, 홈·목록의 최근 메시지 순서, 읽음 표시는 012 에서 다룬다. 브라우저 푸시 알림은 하지 않는다.
- 소리 보관 기간은 학습방에 멤버가 남아 있는 동안이다. 둘 다 나가면 지운다.
- 메시지 스크립트·번역 결과를 계정에 저장해 두 사람이 나눠 쓰는 것은 범위 밖이다.
- 소리 하나의 크기는 60초 녹음의 실제 크기로 충분히 작다. 크기 상한은 plan 에서 정한다.

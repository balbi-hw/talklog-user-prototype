# Feature Specification: 학습 기록을 계정에 저장하기

**Feature Branch**: `010-account-sync` | **Created**: 2026-11-02 | **Status**: Implemented (실제 DB 적용·검증 대기)
**Input**: 3단계 — 로그인(009) 다음, 학습 짝 메시지 수신(011) 전. 사용자 결정: 기존 기기 기록은 **가져올지 묻는다**, 로그인하지 않으면 **지금처럼 기기에 저장**한다.
**서브도메인**: 계정(Generic)이 표현 학습·복습·학습 관계 기록에 "누구의 것인지"를 준다. **흐름**: draft.md §4 의 표현 저장·카드·복습·학습방 단계가 기기를 바꿔도 이어진다.

009 FR-006("로그인해도 기록은 이 기기에만")은 이 기능으로 대체된다.

## User Scenarios & Testing

### User Story 1 - 로그인하면 기록이 계정에 저장된다 (Priority: P1)

로그인한 학습자가 학습방을 만들고, 표현을 저장하고, 복습하면 그 기록이 계정에 저장된다. 다른 기기나 브라우저에서 같은 계정으로 로그인하면 같은 기록이 보인다.
**Why this priority**: 학습 짝에게 메시지를 보내려면(011) 기록이 서버에 있어야 한다.
**Independent Test**: 로그인 → 학습방 만들기 → 다른 브라우저 프로필에서 로그인 → 같은 학습방.

**Acceptance Scenarios**:
1. **Given** 로그인 상태, **When** 학습방을 만들거나 지운다, **Then** 화면은 즉시 바뀌고 잠시 뒤 계정에 반영된다.
2. **Given** 로그인 상태, **When** 표현을 저장·편집·삭제하거나 복습에 응답한다, **Then** 같은 방식으로 계정에 반영된다.
3. **Given** 다른 기기의 같은 계정, **When** 로그인하거나 앱 창으로 돌아온다, **Then** 계정의 최신 기록을 받아 온다.
4. **Given** 로그인 직후, **When** 계정 기록을 받아 오는 중, **Then** 기기 기록을 잠깐 보여 주지 않고 받아 오는 중임을 알린다.

### User Story 2 - 기기 기록을 계정으로 가져오기 (Priority: P1)

**Why this priority**: 지금까지 기기에 쌓은 기록을 잃지 않아야 한다.
**Independent Test**: 로그아웃 상태에서 기록을 만든 뒤 로그인 → 질문 → 가져오기 → 계정에 보인다.

**Acceptance Scenarios**:
1. **Given** 기기에 학습방·표현이 있고 이 계정에서 아직 가져오지 않음, **When** 로그인해 계정 기록을 받아 온다, **Then** "이 기기의 기록을 계정으로 가져올까요?"와 개수가 보인다.
2. **Given** 질문, **When** 가져오기, **Then** 중복(같은 학습방 id, 같은 표현 본문)은 건너뛰고 가져온 수·건너뛴 수를 알린다. 가져온 표현의 복습 기록도 함께 옮긴다.
3. **Given** 질문, **When** 나중에 또는 Escape, **Then** 아무것도 옮기지 않는다. 다음 로그인 때 다시 묻고, 계정 화면에서 언제든 가져올 수 있다.
4. **Given** 가져온 뒤, **When** 다시 로그인한다, **Then** 다시 묻지 않는다.

### User Story 3 - 연결이 끊겨도 기록을 잃지 않는다 (Priority: P2)

**Why this priority**: 모바일에서 연결은 자주 끊긴다. 저장 실패가 학습을 막으면 안 된다 (원칙 V).
**Independent Test**: 연결을 끊고 학습방을 만든 뒤 연결 복구 → 계정에 반영.

**Acceptance Scenarios**:
1. **Given** 연결 끊김, **When** 기록을 바꾼다, **Then** 화면과 이 기기에는 저장되고 "연결되면 보낼 변경이 N건 있어요"가 보인다.
2. **Given** 보낼 변경이 있음, **When** 연결이 돌아오거나 창으로 돌아오거나 다시 시도를 누른다, **Then** 보내고 알림이 사라진다.
3. **Given** 보낼 변경이 있음, **When** 로그아웃을 누른다, **Then** 확인 단계에서 그 변경이 사라진다고 경고한다.

### User Story 4 - 로그인하지 않아도 지금처럼 (Priority: P1)

**Acceptance Scenarios**:
1. **Given** 로그아웃 또는 키 없는 환경, **When** 앱을 쓴다, **Then** 기록은 지금처럼 이 기기에 저장되고 동기화 알림이 없다.
2. **Given** 로그인했다가 로그아웃, **When** 기록을 본다, **Then** 로그인 전 기기 기록이 그대로 보이고 계정 기록은 이 기기에 남지 않는다.

### Edge Cases

- 처음 로그인했는데 계정 기록을 받아 오지 못하면(연결 없음·서버 오류) 기록 화면은 저장소를 쓸 수 없는 상태로 보이고, 상단 알림에 다시 시도가 있다. 빈 목록으로 보이지 않는다.
- 받아 오는 동안 바꾼 기록은 받아 온 값 위에 다시 얹는다.
- 같은 항목을 여러 번 바꾸면 마지막 상태 하나만 보낸다.
- 서버가 거부한 변경(제약 위반 등)은 대기열에 남고 "계정에 보내지 못한 변경이 N건" 으로 보인다.
- 녹음한 음성 메시지와 메시지별 스크립트·번역·다듬기 결과는 이번 범위가 아니다 (지금처럼 메모리).
- 여러 기기에서 같은 항목을 동시에 바꾸면 나중에 보낸 쪽이 남는다.

## Requirements

### Functional Requirements

- **FR-001**: 로그인 상태에서 학습방·표현·복습 기록은 계정(Supabase)에 저장된다.
- **FR-002**: 로그아웃 상태와 키 없는 환경에서는 지금처럼 이 기기(`talklog.*`)에 저장된다.
- **FR-003**: 로그인하면 계정 기록을 받아 온다. 받아 오기 전에는 기록 화면을 loading 으로 두고, 처음 받아 오지 못하면 실패로 보인다.
- **FR-004**: 기기에 기록이 있고 이 계정에서 가져오기를 처리하지 않았으면 로그인 직후 가져올지 묻는다. 가져오기는 중복을 건너뛰고 결과 수를 알린다. 기기 기록은 지우지 않는다.
- **FR-005**: 계정 화면에서 기기 기록을 언제든 가져올 수 있다.
- **FR-006**: 변경은 이 기기에 먼저 저장하고 대기열로 보낸다. 실패하면 남겨 두고 연결 복구·창 복귀·다시 시도에서 다시 보낸다.
- **FR-007**: 동기화 상태(받아 오는 중·보내는 중·보낼 변경 N건·실패·저장됨)를 계정 화면에, 문제가 있을 때는 상단 알림으로 보인다.
- **FR-008**: 창으로 돌아오면 계정 기록을 다시 받아 온다.
- **FR-009**: 사용자가 로그아웃하면 이 기기의 계정 사본과 대기열을 지운다. 보낼 변경이 있으면 확인 단계에서 경고한다.
- **FR-010**: 서버 테이블은 모두 RLS 로 주인만 읽고 쓴다. 익명 역할에는 권한이 없다.
- **FR-011**: 화면 문구는 사실과 맞아야 한다 — 로그인 상태에서는 기록이 계정에 저장되고 녹음은 올라가지 않는다고 알린다 (원칙 II).

### Key Entities

- 기록 범위: 미정 · 기기 · 계정(받아 옴 여부).
- 대기열: 항목별 마지막 변경(갱신·삭제).
- 서버 행: rooms · expressions · review_records, 모두 `user_id` 소유.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 로그인 상태의 기록 변경이 연결된 상태에서 2초 안에 계정에 반영된다.
- **SC-002**: 연결이 끊긴 동안 바꾼 기록이 복구 후 100% 계정에 반영된다.
- **SC-003**: 가져오기 후 계정에 같은 표현 본문이 두 번 있지 않다.
- **SC-004**: 로그아웃 후 이 기기에 계정 사본 키가 0개다.
- **SC-005**: 다른 사용자 토큰으로는 남의 행을 읽거나 쓸 수 없다 (RLS).

## Assumptions

- 서버 테이블은 `supabase/migrations/` 의 SQL 로 만든다. 저장소 GitHub 연동이 master 병합 때 적용하거나, 사용자가 SQL Editor 에서 실행한다.
- 실시간 구독(다른 기기의 변경을 즉시 받기)은 범위 밖이다. 로그인·창 복귀 때 받아 온다.
- 충돌 해결은 항목 단위 마지막 쓰기 우선이다.

## Clarifications

- 기존 기기 기록은? → 로그인 직후 가져올지 묻는다 (사용자 결정).
- 로그아웃 상태 저장은? → 지금처럼 기기에 저장한다 (사용자 결정).
- 화면의 저장 함수가 동기인데 서버 저장은 비동기다 → 로컬 우선 + 대기열 (research R1).
- 로그아웃 때 계정 사본은? → 공용 기기를 고려해 지운다 (research R5).

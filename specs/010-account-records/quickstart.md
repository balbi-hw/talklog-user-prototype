# Quickstart: 학습 기록을 계정에 저장하기

## 준비
1. Supabase 대시보드 **SQL Editor** 에서 `supabase/migrations/20261102020000_account_records.sql` 을 실행한다 (또는 GitHub 연동으로 master 병합 시 적용).
2. **Table Editor** 에 `rooms`·`expressions`·`review_records` 가 RLS enabled 로 보이는지 확인한다.
3. `.env.local` 의 Supabase 두 변수, `npm.cmd run build` → `npm.cmd run start`.

## 자동 시나리오 (가짜 Auth·PostgREST, 실제 브라우저)

| ID | 준비 | 조작 | 기대 |
| --- | --- | --- | --- |
| A1 | 기기에 학습방 1·표현 2·복습 2 | 로그아웃 상태로 열기 | 기기 학습방 보임 |
| A2 | 서버에 학습방 1·표현 1(기기 표현과 본문 같음) | 가입(세션 있음) | 가져오기 질문, "학습방 1개, 표현 2개", 포커스 "가져오기" |
| A3 | A2 | 가져오기 | "학습방 1개, 표현 1개… 1개는 건너뛰었어요", 서버 학습방 2·표현 2·복습 1(가져온 표현 것), 모든 행 user_id |
| A4 | 로그인 | 대화 목록 | 서버 학습방 + 가져온 학습방 |
| A5 | 로그인 | 학습방 만들기 | 서버에 upsert |
| A6 | 연결 끊김 | 학습방 만들기 | 화면에 저장, 상단 "연결되면 보낼 변경이 1건" |
| A7 | A6 | 연결 복구 → 다시 시도 | 서버 반영, 알림 사라짐 |
| A8 | 로그인 | 학습방 지우기 | 서버 delete |
| A9 | 로그인 | 새로고침 | 로그인 유지, 계정 학습방, 질문 없음 |
| A10 | 연결 끊김 + 변경 1건 | 로그아웃 | 경고 "보내지 못한 변경이 1건", 확정 후 `talklog.account.*` 0개, 기기 학습방만 |
| A11 | A10 | 다시 로그인 | 질문 없음, 계정 화면에 "계정으로 가져오기", "기록이 계정에 저장돼 있어요." |
| A12 | `.env.local` 없이 build | 열기 | 기기 학습방, 동기화 알림 없음, 계정 "쓸 수 없음" |
| A13 | 전 과정 | — | 페이지 오류 0 |

## 실제 DB 시나리오 (마이그레이션 적용 후, 수동 또는 검증자)

| ID | 조작 | 기대 |
| --- | --- | --- |
| R1 | 실제 계정으로 로그인, 표현 저장·편집·삭제, 복습 응답 | Table Editor 에 반영 |
| R2 | 다른 브라우저 프로필로 같은 계정 로그인 | 같은 학습방·표현·복습 상태 |
| R3 | 계정 B 로 로그인 | 계정 A 기록이 보이지 않음 (RLS) |
| R4 | publishable key 만으로 `GET /rest/v1/expressions` (로그인 없이) | 빈 배열 또는 권한 오류, 행 0 |
| R5 | 오프라인으로 표현 저장 → 온라인 | 계정에 반영 |

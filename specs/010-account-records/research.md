# Research: 학습 기록을 계정에 저장하기

## R1. 로컬 우선 + 대기열
- 결정: 화면 훅(`useRooms`·`useExpressions`·`useReviews`)의 동기 API 를 그대로 둔다. 저장 함수는 지금 범위의 로컬 키에 쓰고, 계정 범위면 이전 값과 비교한 변경을 대기열에 남긴다. `record-sync.ts` 가 대기열을 Supabase 로 보낸다.
- 근거: 저장·편집·삭제·복습 응답은 이벤트 핸들러에서 결과를 바로 돌려주는 계약이다(002·003·005). 비동기로 바꾸면 세 기능의 화면 상태를 모두 다시 설계해야 한다. 로컬 우선이면 연결이 끊겨도 기록을 잃지 않는다(원칙 V).
- 대안: 훅을 서버 직접 호출로 바꾸기 — 처리 중·실패 상태가 모든 저장 지점에 생겨 범위가 커지고 오프라인에서 저장이 막힌다. 기각.

## R2. 기록 범위(scope)
- 결정: `record-scope.ts` 가 `pending`·`device`·`account(loaded)` 를 가진다. 키는 기기 `talklog.<이름>`, 계정 `talklog.account.<user id>.<이름>`.
- 근거: 기기 키 이름을 바꾸지 않아 기존 사용자 기록이 그대로 읽힌다. 계정 사본을 기기 키와 분리해야 로그아웃 때 기기 기록이 섞이지 않는다.
- `pending` 동안 훅은 읽지 않고 loading 이다. 기기 기록을 잠깐 보였다가 계정 기록으로 바꾸면 사용자는 기록이 바뀌었다고 오해한다.
- 계정 기록을 아직 받아 오지 못했으면(`loaded=false`) 읽기를 실패로 다룬다. 빈 목록으로 보이면 "기록이 사라졌다"로 읽힌다(원칙 II).

## R3. 받아 오기
- 결정: 로그인·창 복귀·연결 복구·다시 시도에서 세 테이블을 모두 받아 오고, 받아 온 값 위에 대기열을 다시 얹어 로컬 사본을 바꾼다.
- 근거: 기록 수가 사람 한 명 분량(수백 행)이라 전체 받기가 단순하고 충분하다. 대기열을 다시 얹어야 받아 오는 동안의 변경을 잃지 않는다.
- 실시간 구독은 011(메시지 수신)에서 다룬다.

## R4. 대기열 합치기·보내기
- 결정: 항목(컬렉션+id)마다 마지막 변경만 남긴다. 보낼 때 삭제를 먼저, 갱신(upsert)을 나중에 보낸다. 보낸 항목은 seq 로 골라 지운다 — 보내는 동안 같은 항목이 다시 바뀌면 새 seq 라 남는다.
- 실패 분류: 네트워크·시간 초과는 `offline`(15초 뒤 재시도), 그 밖은 `error`(60초 뒤 재시도). 둘 다 대기열을 지우지 않는다.

## R5. 로그아웃 때 계정 사본 지우기
- 결정: 사용자가 로그아웃을 확정하면 `talklog.account.<id>.*` 를 지운다. 보내지 못한 변경이 있으면 확인 단계에서 경고한다.
- 근거: 공용 기기에서 다음 사람이 계정 기록을 볼 수 없어야 한다. 세션 만료처럼 사용자가 고르지 않은 로그아웃에서는 지우지 않는다.
- 가져오기 처리 표시(`talklog.import-handled.<id>`)는 지우지 않는다. 다시 로그인할 때마다 묻지 않기 위해서다.

## R6. 가져오기 중복 기준
- 결정: 학습방은 id, 표현은 `normalizeTerm` 본문(002 의 중복 기준과 같음). 복습 기록은 가져온 표현의 것만.
- 근거: 같은 표현을 두 카드로 만들지 않는 것이 002 FR-021 이다. 건너뛴 표현의 복습 기록을 옮기면 계정 표현의 복습 상태를 덮어쓴다.

## R7. 테이블 설계
- 결정: `rooms`·`expressions`·`review_records`, 기본 키 `(user_id, id)`. id 는 클라이언트가 만든 문자열. 시각은 클라이언트와 같은 epoch ms(`*_ms bigint`). 복습 기록에 외래 키를 두지 않는다.
- 근거: 클라이언트 id 를 그대로 쓰면 가져오기·대기열이 id 를 바꾸지 않아도 된다. 복습 기록은 클라이언트가 읽을 때 남은 표현으로 거른다(003). 외래 키가 있으면 보내는 순서에 따라 거부될 수 있다.
- RLS: 행동별 정책 4개, `to authenticated`, `(select auth.uid()) = user_id`, update 는 using + with check. anon 권한 회수, authenticated 명시 부여(Data API 설정에 따라 새 테이블이 자동으로 열리지 않을 수 있음).

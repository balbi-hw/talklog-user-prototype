# Quickstart: 스크립트에서 표현 선택·저장 검증

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-09

Constitution 개발 워크플로에 따라 자동화 테스트를 두지 않는다. 아래 시나리오가 유일한
수용 검증 수단이며, 구현 완료를 보고하기 전에 전부 통과해야 한다.

## 사전 조건

- Node.js 20 이상
- 001과 달리 secure context 제약이 없다. `getSelection` 과 `localStorage` 는 어느
  주소에서나 동작하므로 LAN IP 로 접속해 실제 휴대폰에서 확인해도 된다. 모바일 롱프레스
  선택은 실기기에서만 제대로 확인할 수 있으므로 **S3 은 실기기 권장**이다.

## 실행

```powershell
npm.cmd install
npm.cmd run dev
```

홈 → "유키와 일본어 대화" → 학습방 → 유키 메시지의 **스크립트** 토글을 열면 시작 지점이다.

## 빌드 게이트

```powershell
npm.cmd run build
```

TypeScript 오류 0개로 통과해야 한다 (Constitution 품질 게이트).

## S1. 스크립트에서 표현을 골라 저장 (US1, P1)

| # | 조작 | 기대 결과 | 요구사항 |
|---|------|-----------|----------|
| 1 | 스크립트를 열지 않은 상태로 화면을 본다 | 표현을 고를 수단이 없다 | FR-006 |
| 1a | 스크립트를 열고 아무것도 고르지 않은 상태를 본다 | 저장을 시작할 수단이 없다 | FR-004 |
| 2 | 스크립트를 열고 `過ごした` 부분만 끌어서 고른다 | 고른 글자가 표시되고 저장 수단이 스크립트 **아래에** 나타난다 | FR-001, FR-002, FR-003 |
| 3 | 스크립트 밖의 다른 텍스트(학습 짝 이름, 번역)를 고른다 | 저장 수단이 나타나지 **않는다** | R-001 |
| 4 | 다시 `過ごした` 를 고르고 저장을 시작한다 | 표현 입력칸이 `過ごした` 로 채워지고 뜻 입력칸이 빈 상태로 나타난다 | E2 |
| 5 | 뜻을 비운 채 저장을 누른다 | 저장이 막히고 **"뜻을 적어주세요"가 화면에 문구로** 보인다 | FR-008 |
| 6 | 표현 입력칸을 `過ごす` 로 고친다 | 고칠 수 있다 (다시 고르러 돌아가지 않아도 된다) | FR-002a, FR-009 |
| 7 | 다시 `過ごした` 로 되돌리고 뜻에 "보내다, 지내다" 를 적고 저장한다 | 저장 완료가 표시되고 입력 영역이 닫힌다 | FR-007, FR-012 |
| 8 | 한 글자만(`過`) 골라 저장을 시작한다 | 단어 경계와 무관하게 받아들여진다 | 결정 D-1, US1-1a |
| 9 | 공백이나 `？` 만 골라본다 | 저장 수단이 나타나지 않는다 | FR-005 |
| 10 | 범위를 고르고 저장을 시작한 뒤 취소한다 | 아무것도 저장되지 않는다 | FR-013 |
| 11 | 입력 중에 스크립트의 다른 곳을 눌러 선택을 푼다 | **입력 중인 뜻이 사라지지 않는다** | 엣지 케이스 |
| 12 | 입력 중에 스크립트 토글을 닫았다 연다 | 초안이 버려지고 저장된 것은 없다 | 엣지 케이스, sheet 조항 11 |

## S2. 카드 목록 (US2, P2)

| # | 조작 | 기대 결과 | 요구사항 |
|---|------|-----------|----------|
| 1 | 저장한 표현이 없는 상태(저장소를 비운 뒤)에서 카드 화면을 연다 | 빈 상태와 저장하는 방법이 안내된다 | FR-019 |
| 2 | 화면이 뜨는 순간을 본다 | 표현이 있을 때 빈 상태 안내가 **한 순간도 보이지 않는다** | R-004 |
| 3 | S1 에서 저장한 표현을 카드 화면에서 확인한다 | 표현 · 뜻 · **예문** · 출처 학습방이 보인다 | FR-016 |
| 3a | 그 항목의 예문과 출처를 확인한다 | 예문이 `週末は何をして過ごしたの？` 전체이고 출처가 "유키와 일본어 대화" 다 | FR-010, FR-011 |
| 4 | 표현을 3개 저장한 뒤 목록을 본다 | 최근에 저장한 것이 먼저 보인다 | FR-017 |
| 5 | 개수 표시를 확인한다 | 실제 저장 개수와 일치한다 | FR-018 |
| 6 | 페이지를 **새로고침**하고 카드 화면을 연다 | 저장한 표현과 뜻과 예문이 그대로 남아 있다 | FR-014 |
| 7 | 아주 긴 뜻(200자 이상)을 저장하고 목록을 본다 | 다른 항목을 밀어내지 않는다 | FR-020 |
| 8 | 하드코딩된 표현 3개를 찾아본다 | `映画館で映画を見る` 등이 **없다** | FR-025 |
| 9 | 각 항목에 재생 버튼이 있는지 본다 | **없다** (표현에는 음성이 없다) | 계약 조항 4 |
| 10 | 복습 관련 표시(`8장`, `복습 시작`)를 본다 | 아직 구현되지 않았음을 알 수 있다. 동작하는 것처럼 보이지 않는다 (003 이후: 실제 복습 진입이 동작한다 — specs/003-review 참고) | FR-026 |

## S4. 중복과 삭제 (US3, P3)

| # | 조작 | 기대 결과 | 요구사항 |

| 1 | 이미 저장한 표현과 같은 범위를 골라 저장을 시작한다 | "이미 저장한 표현이에요" 가 보이고 저장이 비활성이다 | FR-021 |
| 2 | 이때 카드 목록의 개수를 확인한다 | 늘어나지 않았다 | FR-021 |

| 4 | 카드 목록에서 표현의 삭제를 누른다 | 곧바로 지워지지 않고 확인 단계가 나온다 | FR-023 |

## S5. Feedback 화면의 저장 (FR-024)

| # | 조작 | 기대 결과 | 요구사항 |

| 1 | 학습방의 "내 문장을 확인해볼까요?" → Feedback 화면에서 저장을 누른다 | 저장 완료가 표시된다 | FR-024 |

## S6. 저장소를 쓸 수 없는 환경 (FR-015)

| # | 조작 | 기대 결과 | 요구사항 |
|---|------|-----------|----------|
| 1 | 브라우저 사이트 설정에서 **쿠키·사이트 데이터를 차단**하고 새로고침한다 | 카드 화면에 저장할 수 없다는 안내가 보인다. 빈 상태 안내가 아니다 | FR-015, R-004 |
| 2 | 이 상태에서 표현을 저장해본다 | 저장 실패가 알려진다. **성공한 것처럼 보이지 않는다** | FR-015, 원칙 II |
| 3 | 이 상태에서 학습방·홈 화면을 쓴다 | 나머지 기능이 정상 동작한다 | 원칙 V |
| 4 | 설정을 되돌리고 새로고침 후 저장한다 | 정상 저장된다 | 계약 조항 8 |
| 5 | 쓰기만 실패하는 상태(저장소 가득 참)에서 저장한 뒤, 새로고침 없이 공간을 비우고 다시 저장한다 | 적어둔 뜻이 남아 있고 다시 저장하면 성공한다 | 계약 조항 8, sheet 표 `unavailable` 행 |

> 확인할 수 있다.

## 통과 기준

S1~S8의 모든 행이 기대 결과와 일치하고 `npm run build` 가 통과하면 구현 완료로 본다.
하나라도 실패하면 완료로 보고하지 않는다 (Constitution 품질 게이트).

사용자 테스트가 필요한 SC-007(무엇을 저장하는지 혼동하지 않는가) · SC-008(고르는 방법을
설명 없이 찾아내는가)은 참가자 모집이 필요한 프로젝트 활동이며 이 문서의 범위가 아니다.

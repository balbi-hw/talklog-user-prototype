# Contract: 카드 목록 (`ExpressionList`)

**File**: `app/components/ExpressionList.tsx`
**Covers**: FR-016~FR-020, FR-022, FR-023, FR-025, FR-026, FR-029
**Model**: [data-model.md](../data-model.md) §1 §4 §5

## 상태별 렌더링 계약 (원칙 V)

| `status` | `count` | 표시 | 유래 |
|---|---|---|---|
| `loading` | — | 목록 자리를 비워두되 **빈 상태 안내를 보여주지 않는다** | R-004 |
| `ready` | 0 | 빈 상태: 아직 표현이 없다는 것과 저장하는 방법 | FR-019 |
| `ready` | > 0 | 표현 목록 + 개수 | FR-016, FR-018 |
| `unavailable` | — | 이 브라우저에서 표현을 저장할 수 없다는 안내 | FR-015 |

**`loading` 과 빈 상태를 같은 화면으로 처리하면 안 된다.** 표현이 있는 사용자에게도
"저장한 표현이 없어요"가 한 순간 보이고, 사용자는 저장이 사라졌다고 오해한다 (R-004).

## 항목 렌더링

각 표현은 `term` · `meaning` · `example` · `sourceRoom` 을 보여준다 (FR-016).
`example` 을 빼면 FR-010으로 저장한 값을 사용자가 확인할 경로가 없어진다. 순서는
`useExpressions` 가 이미 정렬해 주므로 컴포넌트에서 다시 정렬하지 않는다 (FR-017).

`meaning` 이 아주 길어도 다른 항목을 밀어내지 않아야 한다 — 줄바꿈 또는 말줄임으로
처리한다 (FR-020).

## 삭제 (FR-022, FR-023)

| # | 상태 | 표시 |
|---|---|---|
| 1 | 평소 | 각 항목에 삭제 수단 (`aria-label="표현 삭제"`) |
| 2 | 삭제 확인 대기 | 그 항목에 "지울까요?" + 지우기 · 취소 |
| 3 | 삭제 완료 | 목록에서 사라지고 개수가 줄어든다 |

되돌릴 수 없는 동작이므로 확인 단계를 반드시 거친다 (FR-023, 원칙 V).

## 원칙 II 조항 — 지금 화면에 남아 있는 가짜들

1. **FR-025**: 하드코딩된 표현 3개(`映画館で映画を見る` · `久しぶりだね` ·
   `楽しみにしている`)와 `전체 23` 표시를 제거한다. 실제 저장한 표현만 렌더링한다.
2. **FR-026**: 카드 화면의 복습 관련 표시(`오늘의 복습`, `8`, `장 남았어요`,
   `복습 시작 →`)는 복습 서브도메인 미구현이므로 실제 개수와 무관하다. 실제 값으로
   바꿀 수 없으므로 **아직 구현되지 않았음을 알 수 있게** 표시한다. 동작하는 것처럼
   보이는 버튼을 남겨서는 안 된다.
3. 필터 행(`전체 23` · `최근 저장` · `어려워요`)도 동작하지 않는다. `전체`는 실제
   개수로 바꾸고, 동작하지 않는 필터는 제거하거나 미구현임을 표시한다.
4. 각 항목의 재생 버튼(`▶`)은 표현에 음성이 없으므로 제거한다. 001의 FR-016과 같은
   문제다 — 재생할 소리가 없는 재생 버튼을 두지 않는다.

## 조항

5. 모든 컨트롤은 `<button>` 요소이며 아이콘만 있는 컨트롤은 `aria-label` 을 가진다

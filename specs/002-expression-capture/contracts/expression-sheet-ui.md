# Contract: 표현 저장 수단 (`ExpressionSheet`)

**File**: `app/components/ExpressionSheet.tsx`
**Covers**: FR-002a, FR-003, FR-007, FR-008, FR-009, FR-012, FR-013, FR-021, FR-029
**Model**: [data-model.md](../data-model.md) §2 §5

## 배치 (R-006)

선택 위에 떠 있는 말풍선이 아니라 **스크립트 블록 바로 아래에 붙는 고정 영역**이다.

모바일에서 길게 눌러 텍스트를 고르면 브라우저가 자체 복사·공유 메뉴를 선택 위에 띄운다.
그 위치에 우리 버튼을 두면 가려진다. 브라우저 기본 메뉴의 위치는 통제할 수 없으므로
애초에 겹치지 않는 곳에 둔다. 모바일 우선(원칙 III)이므로 모바일이 기준이다.

## 상태별 렌더링 계약

| 상태 | 표시 | 유래 |
|---|---|---|
| 선택 없음, 초안 없음 | 아무것도 렌더링하지 않는다 | FR-004 |
| 선택 유효, 초안 없음 | 고른 글자 + "이 표현 저장하기" 버튼 | FR-003, E1 |
| 초안 있음 | 표현 입력칸(고른 글자로 채워짐) + 뜻 입력칸 + 저장 · 취소 | E2 |
| 초안 있음, `duplicateOf` | 위에 더해 "이미 저장한 표현이에요" + 저장 비활성 | FR-021, E7 |
| 초안 있음, `!savable` | 저장 비활성 + 이유 문구 | FR-008, E6 |
| 저장 직후 | 완료 표시. 초안이 닫힌다 | FR-012, E5 |
| `status === "unavailable"` | 저장할 수 없다는 안내 + 저장 비활성 | FR-015, E8 |

## 조항

1. 표현 입력칸은 고른 글자로 채워지되 **사용자가 고칠 수 있다**. 범위를 조금 넓게
   골랐을 때 다시 고르러 돌아가지 않아도 된다 (FR-002a, FR-009).
2. 예문은 보여주기만 하고 고칠 수 없다. 예문은 "실제로 이렇게 들었다"는 기록이므로
   고치면 근거가 사라진다 (data-model.md §2).
3. 저장 버튼이 비활성일 때 **이유가 화면에 문구로 보여야** 한다. `title` 속성만으로는
   모바일에서 읽을 수 없다 (FR-008).
4. 실패 이유별로 서로 다른 문구를 쓴다 — `invalid-meaning`("뜻을 적어주세요"),
   `duplicate`("이미 저장한 표현이에요"), `storage-unavailable`("이 브라우저에서는 표현을
   저장할 수 없어요"). 같은 문구로 합치면 사용자가 무엇을 해야 할지 알 수 없다.
5. 취소하면 아무것도 저장되지 않고 초안이 사라진다 (FR-013).
6. 선택이 풀려도 초안은 유지한다. 입력 중인 뜻을 잃게 해서는 안 된다.
7. 모든 컨트롤은 `<button>` 과 `<input>`/`<textarea>` 요소다. 입력칸에는 보이는
   `<label>` 또는 `aria-label` 이 있어야 한다 (FR-029).
8. 저장 완료 표시는 `role="status"` 로 알린다 (FR-012, 원칙 III).
9. 신규 스타일은 `app/globals.css` 에 시맨틱 클래스로 추가하고 기존 CSS 변수만 쓴다.

# Quickstart: 실제 음성 녹음·재생 검증

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-09

Constitution 개발 워크플로에 따라 이 기능은 자동화 테스트를 두지 않는다. 아래 시나리오가
유일한 수용 검증 수단이며, 구현 완료를 보고하기 전에 전부 통과해야 한다.

## 사전 조건

- Node.js 20 이상, 마이크가 연결된 기기
- `getUserMedia`는 secure context를 요구한다 → **`http://localhost:3000`으로 접속해야
  한다.** LAN IP(`http://192.168.x.x:3000`)로 접속하면 녹음이 동작하지 않는다 (R-002의
  `SecurityError` 경로).

## 실행

```powershell
npm.cmd install
npm.cmd run dev
```

브라우저에서 `http://localhost:3000` → 홈에서 "유키와 일본어 대화" 카드 → 학습방 진입.

## 빌드 게이트

```powershell
npm.cmd run build
```

TypeScript 오류 0개로 통과해야 한다 (Constitution 품질 게이트).

## S1. 녹음 → 미리 듣기 → 다시 녹음 → 전송 (US1, P1)

| # | 조작 | 기대 결과 | 요구사항 |
|---|------|-----------|----------|
| 1 | 학습방에 진입만 한다 | 마이크 권한 팝업이 뜨지 **않는다** | FR-017 |
| 2 | 마이크 버튼을 누른다 | 권한 팝업이 뜨고, 요청 중임이 화면에 표시된다 | FR-018 |
| 3 | 권한을 허용한다 | 녹음이 시작되고 시간이 1초마다 올라간다. 녹음 중임이 시각적으로 구분된다 | FR-002, FR-003 |
| 4 | 3초쯤 말한 뒤 버튼을 다시 누른다 | 녹음이 멈추고 미리 듣기·다시 녹음·취소·전송이 나타난다. **대화에 메시지가 추가되지 않는다** | FR-004 |
| 5 | 그대로 10초 기다린다 | 자동 전송되지 않는다 | US1-7 |
| 6 | 미리 듣기를 누른다 | 방금 녹음한 내 목소리가 들리고 재생 중임이 표시된다 | FR-005 |
| 7 | 다시 녹음을 누른다 | 시간이 0에서 다시 시작된다 | FR-006 |
| 8 | 5초쯤 말한 뒤 멈추고 전송을 누른다 | 대화 맨 아래에 내 음성 메시지가 추가되고, 녹음 영역이 초기 상태로 돌아간다 | FR-008 |
| 9 | 추가된 메시지의 표시 길이를 확인한다 | 실제 녹음 길이와 1초 이내로 일치한다 | SC-003 |
| 10 | 브라우저 탭의 녹음 표시를 확인한다 | 녹음 표시가 꺼져 있다 (마이크가 해제됐다) | R-005 |
| 11 | 화면을 새로고침한 뒤, 미리 듣기·다시 녹음을 쓰지 않고 마이크 → 정지 → 전송만 눌러본다 | 조작 3회로 전송이 완료된다 | SC-001 |

## S4. 재생 조율 (US2, P2)

| # | 조작 | 기대 결과 | 요구사항 |
|---|------|-----------|----------|
| 1 | S1에서 만든 내 메시지의 재생 버튼을 누른다 | 소리가 나고 버튼이 일시정지로 바뀌며 진행 표시가 움직인다 | FR-011, FR-014 |
| 2 | 재생 중 같은 버튼을 누른다 | 재생이 멈추고 버튼이 재생으로 돌아간다 | FR-011 |
| 3 | 녹음을 2개 전송한 뒤, 하나를 재생하는 중에 다른 하나를 누른다 | **두 소리가 겹치지 않는다.** 이전 재생이 멈추고 새 메시지가 처음부터 재생된다 | FR-012, SC-005 |
| 4 | 재생 중 화면을 본다 | 어느 메시지가 재생 중인지 버블 자체로 구분된다 | FR-013 |
| 5 | 끝까지 재생한다 | 버튼이 재생 상태로 돌아가고 진행 표시가 처음으로 되돌아간다 | FR-015 |
| 6 | 기존 유키/내 Mock 메시지의 재생 버튼을 확인한다 | 버튼이 **비활성**이고, 재생할 음성이 없는 예시임을 알 수 있다 | **FR-016** |
| 7 | 미리 듣기 재생 중에 대화 메시지를 재생한다 | 미리 듣기가 멈춘다 | FR-012 |

## S5. 권한 거부·장치 없음 (US3, P3)

| # | 조작 | 기대 결과 | 요구사항 |
|---|------|-----------|----------|
| 1 | 브라우저 사이트 설정에서 마이크를 "차단"으로 바꾸고 새로고침 후 마이크 버튼을 누른다 | 차단 안내와 허용 방법이 보이고 다시 시도 버튼이 있다 | FR-019, FR-020 |
| 2 | 이 상태에서 하단 탭으로 홈·카드로 이동한다 | 나머지 기능이 정상 동작한다 | US3-4, SC-004 |
| 3 | 마이크를 "허용"으로 되돌리고 다시 시도를 누른다 | 권한 요청 후 정상 녹음된다 | FR-020, T15 |
| 4 | (가능하면) 마이크를 물리적으로 분리하고 마이크 버튼을 누른다 | "마이크를 찾을 수 없어요" 안내가 나오고 앱이 멈추지 않는다 | FR-019 |
| 5 | 녹음을 시작한 뒤 **녹음 중에** 마이크를 분리하거나, Chrome DevTools 콘솔에서 진행 중인 트랙을 강제 종료한다 | 진행 중인 녹음이 폐기되고 오류 안내가 나오며, 다시 시도로 복귀할 수 있다. 앱이 조작 불가 상태로 빠지지 않는다 | **FR-021** |
| 6 | S5-5 직후 브라우저 탭의 녹음 표시를 확인한다 | 녹음 표시가 꺼져 있다 (오류 경로에서도 트랙이 정리됐다) | R-005 |

각 안내 문구는 서로 달라야 한다. 네 경우가 같은 문구면 FR-019 실패다.

> S5-5는 시작 시점 오류(S5-1·S5-4)와 다른 경로다. `blocked` 전이가 `requesting`에서만
> 아니라 `recording`에서도 일어나는지 확인하는 유일한 시나리오다 (전이 T6).

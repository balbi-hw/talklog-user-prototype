# Feature Specification: 실제 음성 녹음·재생

**Feature Branch**: `001-voice-recording`

**Created**: 2026-09-09

**Status**: Draft

**Input**: User description: "지금은 녹음 버튼을 누르면 타이머만 올라가고 실제로는 아무것도 녹음되지 않는다. 사용자가 실제로 자기 목소리를 녹음하고, 보내기 전에 다시 들어보고, 다시 녹음하거나 취소할 수 있고, 대화에 있는 음성 메시지를 실제로 재생할 수 있게 만들고 싶다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 답장 음성을 녹음해서 보내기 (Priority: P1)

민지는 유키가 보낸 일본어 질문을 듣고 답장을 하려 한다. 마이크 버튼을 눌러 말하기를
시작하고, 말이 끝나면 다시 눌러 녹음을 마친다. 방금 녹음한 자기 목소리를 한 번 들어보고,
발음이 어색해서 다시 녹음한 뒤 마음에 들 때 전송한다. 전송된 답장은 대화에 자기 메시지로
나타난다.

**Why this priority**: `draft.md` §4 핵심 흐름의 8~9단계(답장 음성 녹음·전송)이며, 현재
프로토타입에서 가장 크게 비어 있는 지점이다. 이 스토리만 구현해도 "말하고 → 확인하고 →
보낸다"는 서비스의 핵심 가치가 처음으로 실제로 동작한다.

**Independent Test**: 학습방에서 마이크 버튼을 눌러 실제로 말하고, 미리 듣기로 자기
목소리가 들리는지 확인한 뒤 전송해서 대화에 메시지가 추가되는 것까지 단독으로 확인할 수
있다. 받은 메시지 재생 기능이 없어도 검증 가능하다.

**Acceptance Scenarios**:

0. **Given** 녹음이 진행 중일 때, **When** 경과 시간이 60초에 도달하면, **Then** 녹음이
   자동으로 종료되고 상한 때문에 멈췄음이 표시되며 전송 전 단계로 넘어간다.
1. **Given** 학습방에 있고 마이크 사용이 허용된 상태에서, **When** 마이크 버튼을 누르면,
   **Then** 녹음이 시작되고 경과 시간이 1초 단위로 증가하며 녹음 중임이 화면에 표시된다.
2. **Given** 녹음이 진행 중일 때, **When** 마이크 버튼을 다시 누르면, **Then** 녹음이
   멈추고 미리 듣기·다시 녹음·전송·취소를 선택할 수 있는 상태가 된다.
3. **Given** 녹음을 마친 상태에서, **When** 미리 듣기를 실행하면, **Then** 방금 녹음한
   음성이 재생되고 재생 중임이 표시된다.
4. **Given** 녹음을 마친 상태에서, **When** 다시 녹음을 선택하면, **Then** 이전 녹음이
   버려지고 경과 시간이 0에서 다시 시작된다.
5. **Given** 녹음을 마친 상태에서, **When** 전송을 선택하면, **Then** 해당 음성이 내
   메시지로 대화 맨 아래에 실제 길이와 함께 추가되고 녹음 영역은 초기 상태로 돌아간다.
6. **Given** 녹음을 마친 상태에서, **When** 취소를 선택하면, **Then** 녹음이 버려지고
   대화에는 아무 메시지도 추가되지 않는다.
7. **Given** 녹음을 마친 상태에서, **When** 아무 조작도 하지 않으면, **Then** 자동으로
   전송되지 않는다.

### User Story 2 - 대화의 음성 메시지 재생하기 (Priority: P2)

민지는 대화에 있는 유키의 음성 메시지를 눌러 재생한다. 재생 중에는 어느 메시지가
재생되고 있는지, 얼마나 진행됐는지 보인다. 다른 메시지를 누르면 이전 재생은 멈추고 새
메시지가 재생된다.

**Why this priority**: `draft.md` §4의 5단계(음성 재생)이며 P1이 만든 결과물을 다시 듣는
경로다. 다만 P1의 미리 듣기로 재생 자체는 이미 검증되므로 우선순위가 한 단계 낮다.

**Independent Test**: 대화 화면에서 각 음성 메시지의 재생 버튼을 눌러 소리가 나고 진행
표시가 움직이며, 다른 메시지를 누르면 이전 재생이 멈추는 것을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 대화에 음성 메시지가 있을 때, **When** 재생 버튼을 누르면, **Then** 음성이
   재생되고 해당 메시지의 버튼이 일시정지 상태로 바뀐다.
2. **Given** 음성이 재생 중일 때, **When** 같은 버튼을 다시 누르면, **Then** 재생이
   멈추고 버튼이 재생 상태로 돌아간다.
3. **Given** 음성이 재생 중일 때, **When** 다른 메시지의 재생 버튼을 누르면, **Then**
   이전 재생이 멈추고 새 메시지가 처음부터 재생된다.
4. **Given** 음성이 끝까지 재생됐을 때, **When** 재생이 완료되면, **Then** 버튼이 재생
   상태로 돌아가고 진행 표시가 처음으로 되돌아간다.
5. **Given** 음성이 재생 중일 때, **When** 진행 상황을 보면, **Then** 재생 위치가 파형
   또는 진행 표시로 확인되고 남은 시간 또는 경과 시간을 읽을 수 있다.

### User Story 3 - 마이크를 쓸 수 없을 때 이유를 알기 (Priority: P3)

민지는 브라우저 마이크 권한 요청을 실수로 거부했다. 마이크 버튼을 눌러도 아무 일이 일어나지
않는 대신, 왜 녹음할 수 없는지와 무엇을 하면 되는지 안내를 본다.

**Why this priority**: 흐름의 성공 경로는 아니지만 Constitution 원칙 V(상태 전이 완결성)가
요구하는 필수 경로이며, 권한 거부는 실제 사용자 테스트에서 반드시 발생한다.

**Independent Test**: 브라우저에서 마이크 권한을 차단한 뒤 마이크 버튼을 눌러 안내 문구와
다시 시도 수단이 나타나는지 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 마이크 권한을 아직 결정하지 않은 상태에서, **When** 마이크 버튼을 처음
   누르면, **Then** 권한 요청이 발생하고 요청이 진행 중임이 화면에 표시된다.
2. **Given** 마이크 권한이 거부된 상태에서, **When** 마이크 버튼을 누르면, **Then**
   녹음할 수 없는 이유와 권한을 허용하는 방법이 안내되고 다시 시도할 수단이 제공된다.
3. **Given** 사용 가능한 마이크가 없는 환경에서, **When** 마이크 버튼을 누르면,
   **Then** 마이크를 찾을 수 없다는 안내가 표시되며 앱은 조작 불가 상태로 빠지지 않는다.
4. **Given** 브라우저가 음성 녹음을 지원하지 않을 때, **When** 학습방에 들어가면,
   **Then** 녹음 영역이 지원되지 않음을 알리는 상태로 표시되고 나머지 화면은 정상
   동작한다.

---

### Edge Cases

- 녹음 중 60초 상한에 도달하면 어떻게 되는가? (FR-009 / FR-009a)
- 아무 소리도 담기지 않은(길이 0에 가까운) 녹음을 전송하려 하면 어떻게 되는가?
- 녹음 중 다른 화면(홈·카드)으로 이동하면 녹음은 어떻게 되는가?
- 녹음 중 브라우저 탭을 벗어나거나 화면이 꺼지면 어떻게 되는가?
- 녹음 중 마이크 권한이 회수되거나 장치가 연결 해제되면 어떻게 되는가?
- 미리 듣기 중에 다시 녹음을 누르면 재생은 어떻게 되는가?
- 페이지를 새로고침하면 전송했던 녹음은 어떻게 되는가?
- 이미 있던 Mock 음성 메시지는 실제 재생할 소리가 없는데 재생 버튼을 누르면 어떻게 되는가?

## Requirements *(mandatory)*

### Functional Requirements

**녹음**

- **FR-001**: 사용자는 학습방에서 마이크 버튼 하나로 녹음을 시작하고 종료할 수 있어야 한다.
- **FR-002**: 시스템은 녹음 중 경과 시간을 1초 단위로 표시해야 한다.
- **FR-003**: 시스템은 녹음 중임을 시간 표시 외에 시각적으로도 구분해서 표시해야 한다.
- **FR-004**: 시스템은 녹음을 종료한 뒤 전송 전 단계를 반드시 거치게 해야 하며, 녹음
  종료가 곧 전송이 되어서는 안 된다.
- **FR-005**: 사용자는 전송 전 단계에서 방금 녹음한 음성을 재생해 들어볼 수 있어야 한다.
- **FR-006**: 사용자는 전송 전 단계에서 이전 녹음을 버리고 다시 녹음할 수 있어야 한다.
- **FR-007**: 사용자는 전송 전 단계에서 녹음을 전송하지 않고 취소할 수 있어야 한다.
- **FR-008**: 시스템은 전송된 녹음을 내 메시지로 대화에 추가하고 실제 녹음 길이를 함께
  표시해야 한다.
- **FR-009**: 시스템은 녹음 길이를 60초로 제한하고, 60초에 도달하면 녹음을 자동으로
  종료해 전송 전 단계로 넘겨야 한다. 자동 종료된 녹음도 미리 듣기·다시 녹음·전송·취소를
  모두 사용할 수 있어야 한다.
- **FR-009a**: 시스템은 녹음이 상한에 도달해 자동으로 종료됐음을 사용자가 알 수 있도록
  표시해야 한다.
- **FR-010**: 시스템은 소리가 담기지 않았거나 1초 미만인 녹음에 대해 전송을 막고 이유를
  안내해야 한다.

**재생**

- **FR-011**: 사용자는 대화의 각 음성 메시지를 재생하고 멈출 수 있어야 한다.
- **FR-012**: 시스템은 동시에 하나의 음성만 재생해야 하며, 새 재생은 이전 재생을 멈춰야
  한다.
- **FR-013**: 시스템은 재생 중인 메시지가 어느 것인지 시각적으로 구분해야 한다.
- **FR-014**: 시스템은 재생 진행 위치와 시간을 표시해야 한다.
- **FR-015**: 시스템은 재생이 끝나면 해당 메시지를 재생 가능한 초기 상태로 되돌려야 한다.
- **FR-016**: 시스템은 재생할 실제 음성이 없는 기존 Mock 메시지의 재생 버튼을 실제 음성이
  있는 메시지와 구분해서 다뤄야 하며, 동작하지 않는 버튼이 동작하는 것처럼 보여서는 안
  된다.

**권한과 오류**

- **FR-017**: 시스템은 첫 녹음 시도 시에만 마이크 권한을 요청해야 하며, 학습방 진입만으로
  요청해서는 안 된다.
- **FR-018**: 시스템은 권한 요청이 진행 중인 상태를 표시해야 한다.
- **FR-019**: 시스템은 권한 거부·장치 없음·미지원을 서로 구분되는 안내 문구로 표시해야
  한다.
- **FR-020**: 시스템은 권한 거부 상태에서 사용자가 다시 시도할 수단을 제공해야 한다.
- **FR-021**: 시스템은 녹음 도중 오류가 발생하면 진행 중인 녹음을 정리하고 녹음 영역을
  다시 시도 가능한 상태로 되돌려야 한다.

**흐름 유지**

- **FR-022**: 시스템은 녹음 또는 전송 전 대기 상태에서 다른 화면으로 이동하려 할 때
  녹음이 조용히 사라지지 않도록 해야 하며, 사용자가 버릴지 유지할지 알 수 있어야 한다.
- **FR-023**: 시스템은 모든 녹음·재생 컨트롤을 키보드로 조작 가능하게 하고 아이콘만 있는
  컨트롤에 텍스트 대체 설명을 제공해야 한다.

### Key Entities

- **음성 녹음 (Voice Recording)**: 사용자가 방금 만든, 아직 전송되지 않은 음성. 소리
  데이터, 길이, 만들어진 시각을 가진다. 전송되면 음성 메시지가 되고, 취소되거나 다시
  녹음되면 사라진다.
- **음성 메시지 (Voice Message)**: 대화에 놓인 음성. 보낸 사람(나 / 상대), 길이, 보낸
  시각, 재생할 소리의 출처(실제 녹음 / Mock)를 가진다.
- **마이크 사용 상태 (Microphone Availability)**: 미확인 / 요청 중 / 허용 / 거부 / 장치
  없음 / 미지원 중 하나. 녹음 영역이 무엇을 보여줄지 결정한다.
- **재생 상태 (Playback State)**: 지금 재생 중인 대상과 진행 위치. 대화 전체에서 하나만
  존재한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 학습방 진입 후 3번 이하의 조작으로 실제 음성을 녹음해 전송할 수
  있다.
- **SC-002**: 녹음한 음성을 전송 전에 들어보고 다시 녹음할 수 있으며, 전송은 명시적인
  조작 없이는 일어나지 않는다.
- **SC-003**: 전송한 음성 메시지에 표시된 길이가 실제 녹음 길이와 1초 이내로 일치한다.
- **SC-004**: 마이크 권한을 거부한 사용자가 화면의 안내만 보고 무엇을 해야 하는지 알 수
  있으며, 앱의 다른 기능은 계속 사용할 수 있다.
- **SC-005**: 재생 중 다른 메시지를 눌렀을 때 두 소리가 겹쳐 들리지 않는다.
- **SC-006**: 사용자 테스트에서 참가자가 녹음 시작·종료 방법을 별도 설명 없이 찾아낸다
  (`draft.md` §5.4 검증 항목).
- **SC-007**: `README.md`의 미구현 목록에서 "음성 파일 녹음·재생"이 제거된다.

## Assumptions

- 녹음한 음성은 현재 브라우저 세션 안에서만 유지되며 새로고침하면 사라진다. 서버·DB를
  두지 않는 프로토타입이라는 Constitution 기술 제약을 따른 결정이다.
- "전송"은 내 화면의 대화에 내 메시지를 추가하는 것까지를 의미한다. 상대방에게 실제로
  전달되는 실시간 통신은 이 기능의 범위가 아니다.
- 녹음한 음성에 대한 STT 스크립트·번역·AI 교정은 이 기능의 범위가 아니다. 기존 Mock
  피드백 화면을 그대로 둔다.
- 대상 환경은 마이크가 있는 최신 모바일·데스크톱 브라우저이며, 마이크가 없거나 녹음을
  지원하지 않는 환경은 안내 문구로만 대응한다.
- 대화 화면에 이미 있는 Mock 음성 메시지는 실제 소리 파일 없이 유지한다. 새로 녹음한
  메시지만 실제 재생 가능하다.
